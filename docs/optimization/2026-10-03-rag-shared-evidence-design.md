# RAG 第二阶段：共享证据快照设计

日期：2026-10-03。基线：第一阶段实现 `68e100f`，交付文档 `5b10dcb`。

状态：用户已于 2026-10-03 确认设计与实施计划，进入实施。完成状态按实施计划和后续验收记录核对，不能将设计目标当作已实现能力。

## 目标

一次研究中，Analyst、Comparator、Reflector、Writer 和 QA 使用同一份已冻结证据；各自取不同片段，但产品型号、市场、出处、事实值与文档版本一致。Collector 补采或人工介入引入变化时，生成新版本，定位受影响的分析与章节，不让旧分析与新事实混用。

Planner 负责研究范围和历史线索；其输入早于本次采集，不能声称已经看过随后才产生的证据。Collector 的检索仍使用第一阶段的可信范围契约；最终采集清单统一冻结后再供下游使用。

## 已核对的现有结构

- `RunDetail` 已保存 RawSource、CompetitorKB、结构化知识、ClaimCardBundle、SectionBrief 和报告；`RunJournal` 将整个 RunDetail 原子保存为 SQLite JSON。
- 实际图顺序为：collect_join → survey_interview → collect_qa → evidence_hitl → analyst_dispatch；必须把调研补充和半人工介入纳入冻结时点。
- Analyst 当前按产品 / 维度读取 `detail.raw_sources`，其缓存只含原始来源 ID、hash、类型和 URL；事实值或来源时效改变但正文不变时，缓存可能无法表达这种变化。
- Writer 已有 EvidencePack、分段写作和引用检查；SectionBrief 已有允许的来源与卡片 ID，不需要新建平行事实数据库或重写报告系统。
- 企业 `source_snapshots.py` 是网页 / 手动材料附件快照，不能直接替代运行级事实版本快照。

## 方案选择

| 方案 | 收益 | 代价 |
| --- | --- | --- |
| 推荐：运行级快照 + Agent 视图，复用 RunJournal 和现有引用体系 | 输入可复现，版本与依赖可检查；对现有流水线改动集中 | 需要补齐冻结时点、消费记录及失效检查 |
| 每个 Agent 独立查询，只统一检索参数 | 接线少，容易增加独立取证能力 | 同一运行可能读到不同版本，仍缺更正后的依赖失效 |
| 独立事实服务 / 知识图谱 | 适合跨运行、大规模关系探索 | 新增存储与服务维护，当前缺口不需要这一复杂度 |

本阶段采用第一种；真实语义模型、HTTP Qdrant、旧库归属迁移与新草稿界面独立排期。

## 证据契约

### 来源与事实

新增 typed 快照模型，复用已有 RawSource ID、normalized fields 和来源引用。所有工作区 / 项目 / run 身份来自服务端 RunDetail。

来源保存：原 source ID、完整产品 / 覆盖产品、维度、URL、正文 hash、短片段、来源角色、原出版 / 更新 / 抓取 / 核验时间；有知识文档时保存 document ID、chunk ID、版本、hash 和实际文档归属。

事实保存：稳定 fact ID、原 evidence_item_ids、来源 ID、产品、维度、字段、值 / 单位 / 市场、短原文和状态。结构化值保留原 JSON 类型，不把数组或数值格式化成无法回查的自由文本。普通来源仅形成来源信号；没有字段证据时不生成“已核验事实”。

知识文档引用须在可信 scope 内回读 canonical 文档后进入快照；metadata 自称归属、版本或来源时间不构成授权或核验。公共库引用保留显式 null 项目，未知旧归属拒绝进入新运行的可用事实。

日期规则沿用第一阶段：不以构建快照、检索、重排或同步时间刷新事实。价格 / 版本存在原事实日期时不能用本次抓取掩盖过期；未来日期和日期缺失保留明确状态。

同产品 / 型号 / 指标 / 单位 / 市场的不同值记录为未决冲突。两个套餐、不同容量或不同市场不是同一指标；无法确定比较口径时记录不可比较原因，不能用置信度最高的条目默默覆盖。

### 快照与消费记录

快照包含 schema version、snapshot ID、run / workspace / project、单调版本号、父版本、phase、来源清单、事实清单、冲突和缺口，以及内容摘要 hash。

- phase 为 `collect` 的清单可供采集 QA 检查；半人工接受后形成 `analysis` 快照。
- hash 由排序后的身份、来源内容、事实、范围和时间契约计算；创建时间、列表到达顺序和检索分数不改变证据版本。
- 证据契约与 phase 都不变时复用当前快照，不因重复 QA、join 或恢复进程新建版本；collect 转为 analysis 属于明确状态变更。
- 所有视图返回深拷贝；载入和消费时校验 hash，防止嵌套可变对象改写历史快照。
- RunDetail 保存当前指针、已生成快照和消费记录，复用 RunJournal JSON 原子写入；不新增平行数据库。
- 消费记录包含 Agent / 分支 / 章节、snapshot ID、实际选中的 source / fact ID、依赖内容 hash、上下文估计和是否复用旧产物。

已有来源 citation token 保持兼容；fact ID 用于内部依赖和审计，不要求旧报告全面更换引用格式。

## 冻结与运行流程

1. Planner 继续读取原有历史研究提示，并标记为线索；不将历史结论加入当前已核验事实。
2. Collector 按当前授权产品 / 维度检索旧资料、联网补缺；并行分支只提交候选资料，不修改供下游消费的冻结快照。
3. survey_interview 完成后，collect_qa 入口构建采集快照；采集不合格继续按现有预算修复。
4. evidence_hitl 接受后、analyst_dispatch 开始前冻结 analysis 快照。所有分析分支持有同一 snapshot ID；事实修改不能在分支运行中替换其输入。
5. Analyst、Comparator、Reflector、Writer 从该快照取得阶段视图；输出记录消费身份。下游读取上游产物时检查依赖匹配。
6. QA 按报告实际引用的 ID 回查快照和资料版本；不重新宽泛检索以替换报告的证据。
7. 补采或人工导入使证据发生变化时创建新版本；只保留通过依赖比对的旧产物。已开始的旧版本分支可以结束，但不能作为当前版本结果提交。
8. 进程恢复从 RunJournal 读取当前指针和消费记录；不得用当前资料重新拼装旧快照并沿用旧 ID。

没有快照的旧已完成报告继续只读；不会自动升级为本阶段已核验报告。旧未完成运行在安全的分析入口建立首个新快照，或根据缺口进入补采，不能绕过检查。

## 各 Agent 的视图

| 阶段 | 输入 | 必须保留 |
| --- | --- | --- |
| Planner | 研究范围、历史线索和未决问题 | 线索角色及来源，不将历史判断伪装成当前事实 |
| Collector | 按产品 / 维度匹配的旧资料与具体缺口 | 可信 scope、原版本和来源时间；不足时仍补采 |
| Analyst | 当前产品 / 维度的事实、短原文、冲突与缺口 | source / fact ID、值 / 单位 / 市场、snapshot ID |
| Comparator | 同口径事实与有效分析产物 | 不同型号、市场、单位或时间不可比较的原因 |
| Reflector | 当前矩阵与证据覆盖 | 当前快照身份、缺口和冲突，不生成新事实 |
| Writer | 既有 EvidencePack / SectionBrief 的当前证据投影 | 允许的引用 ID 和片段，未决冲突不能写成确定结论 |
| QA | 报告实际引用及对应原文 | 固定 ID、版本、hash、时效；失效项对应明确修复目标 |

整个来源全文继续留在资料库，不复制进快照提示。内部审计身份与产品页面内容分开，暂不新建前端证据编辑器。

## 上下文与 token

视图先按身份、维度、字段和状态筛选，再按片段预算组装；原文与事实成对保留，预算不足时产生 `context_budget_exceeded` 缺口，不能悄悄丢出处。Writer 沿用分段机制，QA 按实际引用分批回查。

初始证据视图预算：quick 8 KiB、standard 16 KiB、deep 24 KiB UTF-8。它们是可评测的初始上限，不是已证明最优参数；Writer / QA 可分段消费，但每段记录预算与选中 ID。现有 LLM 准入使用 UTF-8 字节数 + 256 的保守 token 估计，真实调用仍受原总 token / 费用门禁约束。日志明确标注估计值，不能当成供应商实际 token。

此阶段不增加新的付费模型、embedding 服务或真实联网报告任务。

## 更正、缓存与重做

- 新旧版本按来源 / 事实的语义身份及内容 hash 比对，得到新增、删除、变更和未变集合。
- 缓存身份加入工作区、项目、完整产品、市场、维度、事实值、来源时间与状态的依赖摘要；不能只加入全局 snapshot ID，否则一个事实变化会使所有分析失效。
- 未变分支可复用，并保存其原生成快照和本次依赖验证记录；不能伪造“本次已重跑”。
- 受影响 Analyst 分支、引用其卡片的决策和章节失效；依赖不明时保守重做对应阶段。
- Comparator 的全局决策改变时，依赖该决策的章节也需失效，即使其直接引用的原始资料未改。
- 来源撤销、删除、版本不匹配或权限变化时，当前引用不得发布。历史快照可在原运行权限内作为审计材料读取，不能作为新的有效事实。
- 先接入已有 scoped redo 与 structured repair；未能证明章节依赖完整时保守重写报告，不宣称只重写章节已完成。

## 验收用例

1. 至少两个产品、两个维度的固定回放中，所有下游阶段消费同一 analysis 快照。
2. 改正一个价格且正文 hash 不变：新版本产生，相关 Analyst 缓存失效；其他产品 / 维度的依赖和产物保持不变。
3. 并行旧分支在新版本提交后完成：结果被拒绝提交，不污染新矩阵或报告。
4. 删除或更新被引用文档：QA 返回具体 source / fact ID 和修复范围，不能使用另一次宽泛召回替代原文。
5. 公共库、项目库、其他工作区、错误型号、过期价格、历史报告和伪造 metadata 均按第一阶段契约处理。
6. 进程重开后 snapshot ID、版本、事实值与消费记录完全一致；重复冻结不增加版本。
7. quick / standard / deep 的每段上下文遵守预算，不截断结构化值或丢失出处。
8. 旧报告仍可读取，既有 citation token、OpenAPI 和前端类型保持同步。

只有离线回放、定向回归、独立审查与完整回归通过，才能声明本阶段实现完成。真实语义质量、联网准确性和实测 token 节省留给后续成对验收。
