# RAG 第一阶段实施计划

用户已确认《RAG 核查与证据复用设计》，并选择本阶段使用 Qdrant 本地持久化模式验证；HTTP 服务保持未验收状态。基线为 `0e505b5`，沿用 `codex/pastoral-desktop` 工作区。

## 目标与边界

完整采集正文进入资料库，Agent 保留资料引用和短片段；知识检索、Collector 工具和企业证据同步采用可信工作区 / 项目范围，明确型号、市场、资料角色与来源时间。未归属旧资料不自动共享。

本阶段保持已有关键词检索可用；语义模型部署、索引迁移、各 Agent 的证据快照和新草稿界面属于后续阶段。Qdrant 本地模式验证索引适配、过滤、持久化和删除，不当作 HTTP 服务或语义质量验收。

## 任务 3：入口和采集接线

按依赖顺序拆为 3A（Collector / 工具 / 完整正文）、3B（知识 HTTP / 企业同步 / 后台任务范围）和 3C（持久抓取来源 / 子任务继承范围），每项分别完成规格和质量审查。接线检查发现已有资料回查链接未传项目 ID，因此追加 3D：只衔接现有链接、详情与版本操作的项目范围，防止启用隔离后回查出现 404；不新增项目选择界面。后台任务的列表、详情和结果也保存范围，避免通过任务结果绕过资料访问过滤；抓取来源的归属由服务端保存，不从网页文本推断。

- [x] 知识 HTTP 搜索和资料访问由服务端用户上下文注入工作区；项目必须归属当前有权限工作区。请求正文不能覆盖可信范围。
- [x] Collector 从 RunDetail 注入 workspace / project / competitor / market / 时间政策；工具与企业知识同步使用同一范围契约。
- [x] 在研究结果仍持有 CapturedPage 时保存准入来源对应的完整正文；RawSource 只增加 document ID、版本、hash 等引用，禁止把全文传播到所有 Agent 提示。
- [x] 现有资料回查链接及详情 / 版本操作传入已授权项目上下文；不再通过默认全库读取保证链接可用。
- [x] 外部文本 / 文档 / 抓取入库传入已授权范围；归属未知旧资料明确隔离，修改 / 删除 / 同步不能越界。
- [x] 红测摘要之外的规格可检索、正文不进入 RawSource、请求伪造范围无效、错误项目及旧未知归属资料被拒绝；必要更新旧测试夹具。

## 接线实施细则（供本阶段实施与审查核对）

### 3B：接口、证据同步与后台任务

- 服务端认证用户决定 workspace；请求正文中的 workspace 不能覆盖。project 可显式选择，但必须存在且归属当前可信 workspace；默认无 project 只访问该 workspace 的公共资料库。读公共库的标记不能扩大修改、删除、合并与回滚范围。
- 资料列表、数量、详情、分块、版本、对比、重索引、删除、搜索、统计、评测以及评测结果均执行相同范围约束。未知 ID 或其他范围的 ID 返回未找到。
- crawl_jobs、ingest_jobs、eval_runs 保存范围，旧记录留空；列表和数量在 LIMIT 前过滤。/crawl/jobs 的别名及 SSE 也受保护。后台抓取与批量任务使用创建时已保存的服务端范围，不能从 HTML 或请求当前会话重建。
- 文本、文件、URL 和抓取结果传递相同范围与市场。企业证据同步只选择目标项目及同工作区公共库的 source 角色；historical_report 不投影成实时事实。保留 typed 原核验、出版、抓取时间、版本与 hash，不以本次同步时间提高新鲜度。

### 3C：持久抓取来源

- 来源保存服务端归属，列表、详情、删除、重试、frontier 统计按该归属访问；旧未知来源不自动归属。
- 调度器使用保存的 source_id，而非用户可指定的 run_id 推断归属；子链接继承 source_id。URL 去重限定在同一来源，避免其他来源或项目的相同 URL 挤掉任务。
- 入库 callback 使用保存来源的范围，不接收网页提供的身份。修改和重试不能通过 run_id 碰撞影响其他来源。
- 质量审查复现删除来源与抓取完成 / 入库的并发问题：取消状态不能被成功或失败收尾覆盖，已删除来源不能产生新子链接，首次正文发布须在 SQLite 写事务中再次确认来源仍存在且范围匹配；配置异常不能让任务永久停在 running。

### 3D：现有引用界面衔接

- 新资料引用携带服务端文档项目归属，QA 审计与现有回查链接保持该归属；网页 metadata 不作为项目身份。
- 成功 Capture 单独保留实际抓取核验时间；稳定功能页面可沿用该时间判断已读取事实，缓存保留原 capture 时间，失败页面不能宣称核验。全量回归确认价格 / 版本等日期敏感页面若已有来源日期，不能因今日抓取历史页面而变成当前事实，必须保留原事实时间。
- 仅有来源更新时间的历史价格也不能回退到当日抓取时间。必要追加 typed `source_updated_at`，沿现有时间字段路径贯穿存储、检索和引用；核验、更新、出版、抓取时间分别保留，不把更新时间冒充出版日期，不从旧 generic metadata 自动补归属或时间。
- 候选和抓取结果中的来源日期通过各自明确的字段传递；准入时统一保护出版与更新时间。附加 metadata 不能覆盖候选日期，也不能在候选日期缺失时把通用网页 metadata 升格为来源日期。旧报告链接重新抓取的日期测试迁移到明确字段，保留原断言。
- 另用隔离探测复现 KB 日期适配问题：typed 核验 / 出版时间为空时，原始 metadata 的 `last_verified_at=2099` 会被复制进 RawSource，QA 观察时间随之变为 2099。KB 日期代理字段必须只来自 typed 原文档字段，不能用网页 metadata 填充空值；原始 metadata 可保留出处，不参与事实时效判断。
- 资料页面从回查链接取得项目参数，详情、分块、版本、对比、删除与回滚使用一致范围；服务端始终再次授权。公共库引用不变成项目库写操作。
- 企业报告现有“回滚资料”也必须携带引用的真实项目范围，不能沿用知识页面遗留的全局 store 范围；混合多个写范围的选择不能被合并成一次默认范围的修改。
- 本项只修正因隔离引入的现有功能断链；新项目选择器和证据快照界面仍留待后续阶段。

### 已确认的保守时间策略

重复正文继续保留原文档的来源时间；新实时 RawSource 可记录本次实际捕获时间，引用显示返回的原文档时间。本阶段不把重复入库、查询、缓存命中或同步当成新核验。相同正文的真实复核事件及其向量时间更新，留待后续证据快照阶段设计。

### 最终集成审查跟进

同 hash 的摘要与真实完整正文仍须把资料等级从 summary 单调提升为 full_source，避免后续摘要归档该全文；pipeline 的快速去重与仓库事务内重复检查都必须覆盖。不改变原来源日期、文档版本、正文、分块及索引，来源删除的事务守卫继续有效。

已迁移的库也可能被旧进程重建两条全库唯一索引；初始化须在去重前幂等清理，而非只依赖迁移版本。该增量已通过规格与质量复核，最新服务启动后核对 132 条资料的原字段与备份完全一致，124 条未知工作区资料继续隔离保留。

验收结果和运行环境限制见 [第一阶段验收记录](2026-10-02-rag-stage-one-results.md)。本地 HTTP 只读检查通过；健康汇总仍有既有 Temporal 配置报错，不等同于全环境已就绪。
