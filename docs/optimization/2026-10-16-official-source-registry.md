# 新产品官方来源登记与真实采集

## 已接入的功能

生产 `resolve_competitor_identity` 支持部署者维护的 [official_sources.json](../../backend/packages/business_intel/official_sources.json)，无需按产品增加 Python 判断。当前新增 Miro、Airtable、Trello、Zoom 的已人审官方文档链接；本轮真实生成仅选 Miro/Airtable 的四条来源，不代表四产品全部经过真实模型验收。

每个产品提供：

- `product`、精确匹配的 `aliases`；拒绝与其他登记及内置产品名称/别名归一后碰撞。
- `documents`：`title`、`url`、`dimension`、`reviewed_by`、带 UTC 时区的 `reviewed_at`、`review_basis`。

这里的审核时间只说明官方来源链接何时被确认，不能代替网页采集时间或价格/功能的有效日期。初始登记来自项目用户已确认的 8 题官方来源；未导入参考答案或禁止推断清单，不称第三方独立人审。

## 新增产品的操作

1. 核验产品身份和文档的官方属性，记录可追溯的审核依据；普通搜索结果、用户提供的 URL、模型自称“官方”均只作为候选。
2. 部署者把审核通过的精确文档 URL 与上述审核记录添加到登记文件。文档不能自动授权主页、整域名或同品牌其他产品。模型和研究请求没有登记写入入口。
3. 用默认零调用的 [eval_official_writer.py](../../backend/scripts/eval_official_writer.py) 或相关测试检查登记。文件在进程首次读取时冻结，更新后重启服务；诊断 manifest 和采集回执记录同一个登记 SHA256。
4. 通过正常 Collector 抓取；来源登记只授权尝试核验，不自动生成事实或提高提取置信度。

登记加载只做本地结构验证，不做 DNS、不读取模型配置。拒绝重复 JSON 字段、重复文档、空审核依据、HTTP、IP 字面量、内网域名、凭据、fragment 和非标准端口。真实网络路径继续使用已有 SSRF、DNS 重绑定、robots 和内容检查。需要 query 标识文章的 URL 会完整保留 query，另一篇文章不能复用授权。

## 抓取与证据传递

对新登记产品，capture adapter 不使用候选标题填补缺失的真实网页标题。只有 typed `EvidenceFetchResult` 的完整正文、成功响应、质量和正文哈希均通过后，才可能建立当前采集回执。模型摘要、未知材料、错误标题、未知重定向目标不能因此被升级为官方完整证据。

`official_source_verification` 包含产品、请求/最终 URL、登记 URL、标题、登记版本、正文完整 SHA256、采集时间与原链接审核时间。它是采集完整性与登记匹配记录，不是自然语言主张正确的证明；不信任页面或传入 metadata 预先声称通过的回执。

缓存重绑定会重新核对产品和 URL。完整正文入 canonical 前，再对实际 page 与 RawSource 回执做一致检查；后续仍使用既有项目/工作区、来源角色、版本、URL/哈希和证据准入检查。此次没有新增 canonical 读取后的完整回执复验，也没有给网络每个中间跳转新增“官方属性证明”；这些不列为已验收能力。

有界语义提取仍只选择原文，不让模型提供权限结论、人工角色或答案。操作观察、矩阵、Writer 和逐条审核保持原准入规则；未知的套餐、角色与访问前提仍应保持未知。真实模型仍可能遗漏跨章节条件或错误通过不完整主张，需单独验收。

## 实际测试入口的范围

默认只预览；`--live` 要求冻结数据与登记的两个 SHA256。8 题必须先完成人审。运行时仅发送研究问题和来源标识，不发送固定短节选、参考答案或预期结论。

- 真实 Collector research adapter、抓取/准入/完整正文持久化、共享快照及下游生产阶段。
- 写作调用 `_real_writer_step`，包含证据投影和受保护的产物提交；最终 QA 在失败后仍执行。
- 零准入来源时，不再花费模型额度进行下游比较或反思。
- 沿用原生 24 次调用、80000 token、单次输出 2048、重试 0 上限，总超时默认 600 秒。
- 临时 canonical SQLite、in-memory 运行状态；显式 sparse 并关闭语义向量入库，防止继承外部 embedding/Qdrant 配置。本入口不验收生产语义 RAG。
- 固定官方 URL，不验收自动发现竞品、搜索、阶段 QA、HITL、完整 Graph 终态和正式发布。

真实结果、失败尝试与语义问题见 [本轮交付记录](2026-10-16-official-writer-delivery.md)。
