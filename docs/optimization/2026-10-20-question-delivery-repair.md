## 本轮改了什么

1. **来源与条件窗口**：DeepSeek 当前 Markdown/转义 Markdown 采用明确表示类型和原始字符坐标；绑定局部章节与父级条件，保留完整例外。旧 HTML 诊断不会借给当前来源作事实，缺失 FAQ 继续显示缺口。
2. **逐题派送**：在原有 8 条/14000 bytes 中先安排每题核心事实和例外。检索选中与实际发给 Writer 分开核对；只有 ID、元数据或被截掉的文字均不算送达。不同条件不会按粗类别去重。
3. **逐条引用**：Writer 选择实际发送事实的完整原文片段，由服务器生成可重放绑定。父事实不能补作未绑定子句的支持。中文非操作回答与合格澄清可进入原有双审核，操作陈述仍需明确操作绑定。
4. **金额及范围**：有限语法区分用量单价与账户月最低费，核对套餐、币种、分母、计量对象、周期及账户范围；同行多金额保留不同诊断身份。未证明推导仍阻断。Reflector 实际接收简报，服务端按任务范围过滤明确不适用的比较要求，保留未知和题内缺证。

审查修复了实际 compact 漏核心事实、缺例外的澄清误放、旧 TS 兼容、完整分析/优劣比较误豁免、费率伪装最终账单，以及账户最低费误变每项目费用等反例。首轮失败记录和旧产物保留，没有修改人审答案。

## 独立审读发现

### 答案和记录须分别核对

- **Bitwarden**：免费组织的人数及 collection 限额答对；离职题仅显示尚未核实，没有提出删除账户/移除成员、个人/组织数据的必要澄清。
- **1Password**：访客单库、无 Private vault 及升级身份的边界答对；精确人民币含税价给出具体不足说明，没有编金额。
- **Dropbox**：两题均没有正文及保存回答，属于遗漏。
- **Cloudflare**：限定域的否定回答及 CPU/其他用量不足答复正确。保存的角色题 `reason` 错称未发表的角色定义已经发表，因此该记录整体判错误；正文答案仍正确。账单项原样为 `answered / insufficient / claim_ids=[]`，不能消费为已算出账单，后续需统一不足答复语义。

独立审读复核了 11 组 span 身份/偏移、2 组 operation 身份和 3 次 Writer 输入哈希。报价不足答复没有独立 answer-span 绑定，不宣称它们也通过了逐 span 引用验收。

### 两条已发表额外主张绑定不全

- Bitwarden `claim-9ab929737c081dd635e0` 的 `value/0[290:380]` 只支持移除后保留条目，没有绑定同句“归个人所有”。
- 1Password `claim-4c0d0f4f78709ca279ff` 的 operation 绑定支持接受/确认后的共享前提，没有绑定后半“确认后像家庭成员一样管理访问”。

这些文字可在父原文中找到，并不代表整句已完成绑定。10 条已发表主张中，8 条绑定充分；其余 2 条不能靠 `supported` 标签豁免。

### Reflector 的局部输入仍未与 Writer 对齐

已读取实际模型输入，而非从全量 capture 猜测：

- Bitwarden `span-38` 只选入 Centralize policy/Families 的两条内容事实，未选到 Free 限额。
- 1Password `span-31` 已见单库/Private vault 规则，仍错误要求额外“直接否定”证据。
- Cloudflare `span-33` 见通用范围、Access Policy Admin 等内容，未见 Cache Domain Purge 行与费率表；当前资料和 Writer 已有相应证据。

因此当前部分 blocker 是局部没看到或误读，不等于 Collector 没有采到。服务端没有把未知阻断一律删除，这些问题仍如实暴露。

本次 Cloudflare 未发表美元金额。没有金额阻断不能证明实际网页费率、账户最低费或派生金额已经完成真实消费验收；新金额正例目前只有离线内部链路验证。

1. **先对齐各 Agent 的逐题证据包**：Analyst/Reflector 接收同一核心事实、条件与例外，区分“本次视图未见”和“当前全部资料缺证”；对每条阻断按已绑定证据定向复核。合理不足答复也要成为可交付的明确结局。
