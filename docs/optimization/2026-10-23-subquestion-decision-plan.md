# 子问证据与统一结论实施计划

> 用户已批准本轮方向。使用 systematic-debugging / test-driven-development，独立上下文任务使用 subagent-driven-development，完成后独立规格和代码审查。复用当前隔离工作树 `codex/pastoral-desktop`，基线 `03fa684`。

**目标：** 子问选择可读、完整且可还原的支持；答案审核只使用已发表前提作证明；正文、保存答案和 QA 消费同一最终结论。

**设计：** 沿用已授权设计，保持当前语义采集与逐条主张审核。将短引用的字符位置阅读改为精确文本阅读，服务器仍校验原始身份。独立答案审核区分已发表支持与仅用于否定/限制的源条件，保留主张种类和逐问关系。最终答案作为问题结论的唯一发表入口；未通过答案审核的推断不能在另一正文段落以已确认结论出现。

**技术：** Python、Pydantic、pytest，当前 DeepSeek 兼容适配器与固定官方页面回放。保持原模型预算；不训练、不运行 Docker、不修改人审参考。

## 已复现根因

1. 1Password 实际 Writer 将无 Private vault 规则引用到邀请规则的 s2；真实输入的引用只有位置，须模型自行切原文。重复添加所有 quote 的旧试验会挤掉其他核心规则，不能复用该方案。
2. 答案复审把未发表原文中的无 Private vault 限制当作已发表前提，借“可升级”得出双否定。
3. Cloudflare 复审认为已发表 inference 不应选入答案；payload 未保留 kind，删除结论主张后确定性检查降级，正文却保留同一推断。
4. Trello 输出要求中的“是否存在强制义务”被拆成独立问题；已有子问总结形成重复状态。第二题真正的权限规则需沿原文到准入逐层核对，不能靠参考答案补 runtime。
