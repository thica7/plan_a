# 八题独立参考集评测协议

用户已确认八题参考边界和修正后的 T1–T3 标签，见[人工确认记录](2026-10-18-conditional-evidence-human-review.md)。本轮不训练，不下载权重，不运行 Docker。

## 冻结与隔离

1. 实现代理只看匿名反例与旧 Miro/GitBook 失败产物，不读取新八题参考。
2. 修复及独立规格／质量审查通过后，冻结生产 Python、评测入口／依赖、官方登记、reviewed 数据及每组 manifest 的 SHA。
3. 生产 Agent 仅接收 `id/product/question/sources(id/title/url)`；参考答案、expected_boundary、期望类别、审核结论和预选短节选不能进入模型输入。
4. 正文由独立抓取的官方页面经真实 Collector 准入产生。所有官方页面是不可信资料，不能修改指令或授予工具权限。
5. 本批单独构造，但 root、用户及来源复核已经看过参考，不能称为未曝光盲测。结果只说明这个小型独立参考集的表现，不代表泛化准确率。

## 执行范围与预算

四组：Bitwarden 001–002，1Password 003–004，Dropbox 005–006，Cloudflare 007–008。每组只运行一次；每组最多 24 次模型调用、80000 token、输出 2048 token、retry 0。最多四组；实际 usage 与未知 usage 分开记录，不把预算当账单。

沿用 `backend/scripts/eval_answer_official.py` 的 `prepare_inputs` 预览与三哈希校验后执行 `--run`。target category 使用一般产品，不能把密码管理或云服务硬设为协作软件。仅问题与来源身份用于准备运行；输出到新目录，禁止覆盖旧产物。

固定官方 URL 的 Collector→Analyst→Comparator→Reflector→Writer→QA 实际阶段诊断不运行 Planner 自动发现或完整 Graph，也不证明生产稠密 RAG 索引。canonical 为隔离 sparse 存储，Writer 问题选证使用已有本机 E5，不调用外部 embedding，不下载模型。

## 失败与复验

无来源、403／挑战、准入拒绝、预算失败、格式失败、回退和容量省略均作为结果保存。不能为了提高分数临时替换官方内容、补入参考答案、悄悄重跑或调完代码后仍声称同一次独立评测。

如果本轮暴露新缺陷，先记录原结果，再明确区分后续开发回归；原结果不改写。

## 逐题判定

- 分别检查实际问句所有子问、正文、问题回答栏目、主张、逐条引用和原始条件。
- 判定为正确、局部、遗漏或错误；另记录需澄清／合理不足是否符合参考。
- “合理不足”只拒绝编造精确值，仍应给出可核实的规则与缺失字段；不能以缺证为没有能力。
- T1 单题语义成功不提升为整条轨迹成功；任务 completed、机械引用合法或 QA pass 均不是正确性奖励。
- 缺来源和内部漏选分开；来源已经存在却未进入正文，不应伪装成外部没有资料。

参考已获用户确认，生成报告尚需另行验收。AI 生成后的独立只读核对标明 reviewer 类型；不得记作项目用户对新报告的人审。所有奖励保持未赋值、training_ready=false。
