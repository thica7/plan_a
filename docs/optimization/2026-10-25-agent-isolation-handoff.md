# 子 Agent 隔离验收、共享前提与 Writer 实际交付

日期：2026-10-25。基线：`4165b0418f12920bd1ef3eff7304d29f983838b1`。本轮实现及固定资料诊断已完成，**完整报告仍未达到交付标准，实验入口继续默认关闭**。实施计划见[计划](2026-10-25-agent-isolation-handoff-plan.md)。

## 验收范围

本轮检查两类问题：各 Agent 自身能否履行提示中的任务，以及上游产物是否真正进入后续模型请求。保留现有 LangGraph 和规范证据库，暂不训练模型，实验任务流程默认关闭。

- 资料固定为 2026-10-21 的官方页面快照；四产品为 Trello、Cloudflare、Bitwarden、1Password，固定原八题、拆分后十个内部问题。
- 模型配置固定为 `deepseek-flash`、温度 0、无重试、默认输出上限 2048；底层模型版本未独立确认。
- 每运行仍为 24 次调用、80000 保守 token 预算；最终回答及 QA 预留分别为 12000、11000。
- 参考答案只用于运行后的独立审读，不进入 Agent 输入。原八题已曝光，不是盲测，不作泛化准确率或多 Agent 因果优势结论。
- 阶段回放覆盖生产 Planner 固定范围及 Collector 至 QA；未验证自动发现、新网页抓取、完整 Graph 发布、生产稠密 RAG、多人部署或前端。

## 已修复的功能断点

### 1. 上游产物存在，实验任务生成却没收到

旧实验入口会验证 Analyst、Comparator、Reflector 的产物身份，但 `task_context` 到实际生成之间未传递三项内容。其他非实验写作路径已有上游上下文，不能据此声称整个项目此前都未消费产物。

现在逐任务写作显式传递 `upstream_analysis`、`comparison_assessment`、`reflection_constraints`，并从当前 producer、产品／维度和快照重新验证。只有实际成功 transport 的输入通过核对，才登记消费依赖；零 transport 不算已交付。上游内容属于可错的建议，产品事实仍须绑定规范来源。

真实规模的比较与反思产物可能超过角色配额。新版投影保留状态、完整条目和明确省略计数，分别遵守原 1800／1600 字节配额；不截断句子、条件或例外。服务端代际标记阻止删除字段并重算普通哈希后降级；历史真实旧收据继续按原投影重放。

### 2. 拆题丢失同一原始请求的共享条件

服务器从同产品唯一原始请求恢复完整父文本及稳定身份，建立父题与子问绑定。选择、生成、任务审核、最终回答和独立 QA 保留请求上下文。题设中的身份、套餐、人数和 A/B 设置只是待判断的假设，不是产品事实。

子问保持原文本和 ID，继续作为检索主意图；父题设辅助召回，不把下载、导出等不同子问合成同一查询。跨产品或存在歧义时保留未绑定，不借另一原题的前提。

第三版回放又发现一处接口遗漏：服务器在“？请将……”之间插入空格后，严格子串匹配使Trello投票义务子问失绑。最终父上下文第2版复用原拆分／分组纯逻辑，只有同一原始行能精确产生该完整canonical子问时才补充唯一父匹配；不做任意删空白、跨行或模糊匹配。固定SYSTEM身份选择重建版本，保留历史第1版的真实unbound收据。

### 3. 单 Agent 同批证据因重复内容无法入模

直接对照保留所有规范事实和原始问题，使用完整重复对象与文本共享；服务端解码后对全部 payload、facts 双 SHA 校验，不删事实、qualifier 或来源条件。缺失、循环、歧义引用及篡改拒绝。

输入预留沿用生产的逻辑消息 UTF-8 字节加 256 方法，不把 HTTP JSON 二次转义字节当输入；这不是精确 tokenizer。未知 usage 仍按完整预留计费，没有提高 80000 上限。

### 4. 真实回放暴露选证容量回归

第二版四家回放中，Trello 的11个任务在选证 transport 前全部被标记为 `task_evidence_unavailable`。原件离线重建确认：三建议共 4609 字节，完整父上下文另占空间，四批内部事实窗仅 8068／7640／7453／8186 字节；完整事实尝试加入后全部被移除，catalog 为空。最终四个请求仅 8488／9358／9634／7435 字节，均小于外层 14000 限制。

因此，失败来自装包顺序，不能解释成官网缺证或模型拒答。必要修复是分开候选选择与已选证据写作的上下文；最终复验结果在下一节记录。第二版原件保留，不覆盖失败或隐去成本。

最终实现先给选证装入完整任务、父题设及规范事实，再将三项建议完整附给已选证据的生成和任务审核。后两者仍须满足原窗口；装不下时保留预算延期。候选原件被容量挤空、外层请求超界与真正无原件／无合法引用分别判断。没有裁句、提高预算、改变选证排序或重写模型判断。

新generation的两阶段SYSTEM身份要求对应的新review格式，删除review标记不能降级。历史真实旧generation没有该身份，仍按旧审核格式回放；检查不提供同时伪造全部存储记录的密码学签名保证。

## 验证和比较方法

### 生产入口离线合同

覆盖 Planner、Collector、Analyst、Comparator、Reflector、Writer 和最终 QA 的代表入口；其中新增实际消息捕获、共享前提、生产身份重验、旧收据重放、零 transport、超界与篡改拒绝。合同通过不代表模型语义完成。

### 七类模型请求隔离

`backend/scripts/eval_agent_isolation.py` 按原提示哈希恢复实际 system／user／schema，保留模型、温度、输出上限和原请求字节。各角色只选一条真实请求单独重放；没有真实请求则标未验，不能合成提示补数。

这是模型请求隔离，不覆盖该角色全部工具、准入、解析和持久化闭环。合法 JSON、引用 ID 或成功 HTTP 返回也不授予语义通过。HTTPX 边界是进程内守卫，不是操作系统沙盒。

### 单 Agent 对照

直接 Agent 接收同一次采集产生的全部规范事实、来源及完整原题，不读取旧报告和参考答案。完整阶段流程额外包含上游分析和多级审核，因此两个提示并不完全相同。

成本分别列完整流程、共享 Collector、直接生成新增、直接生成含共享采集；引用分别审读流程中的逐条绑定与直接报告的来源级绑定，不混成相同指标。provider token 不等于美元账单。

### 各角色自身功能与交接分开判断

下表每角色仅一条原提示模型请求重放，**不等于整个 Agent 的工具、准入、解析、存储及全流程验收**。

| 角色 | 狭义请求结果 | 实际发现 |
| --- | --- | --- |
| Planner | 通过 | 保留产品／维度与请求范围；未验自动发现或搜索 |
| Collector | 部分 | 六条语义规则可经布局归一对应正文，未见词汇编造；但同HTML窗口的生产定位准入仅1/6，另5条 `not_original`，原文格式／位置交付仍有缺口 |
| Analyst | 通过 | 本输入保留套餐、投票开关、禁止操作及计费身份；未证明所有产品／维度均合格 |
| Comparator | 通过 | 正确作单产品条件判断且 `winner=null`；未验跨产品同矩阵胜负 |
| Reflector | 通过 | 本返回允许合理条件推论、无阻断；有偏保守的非明示缺口提示 |
| Writer | 部分 | 下载任务正确，但投票规则附加评论这一独立操作，未落实单谓词合同 |
| QA | 失败 | `keep`总体有依据，却要求请求假设中的Premium／Observer由产品来源证明，违背题设与事实分离要求 |

Collector的6/6语义对应不是6/6生产准入。该HTML来源没有允许通用归一的格式身份，不能把去空格／改排版的近似引用直接当作原文；下一步应修复可重放的原文位置映射及实际提取输入，不取消来源校验。1Password报价FAQ只出现在捕获诊断，未成为本次送入模型并准入的规范事实，Writer不能借用。

Bitwarden的明确否定与澄清已在问答区域发表；“暂无观察”来自事实／推断分区，属于容易误解的展示文案，不能误报为事实又丢失。Cloudflare的关键角色／CPU规则确实进入实际选证输入，仍被选证器拒选，属于子Agent理解和选证合同问题。另有Trello任务与事实窗口错配、预算延期及未送审核，不能全部归因于模型或采集缺证。

## 后续优先级

1. **Collector原文定位与规范入库**：修复模型引用与HTML原文的可重放位置映射，保证允许的格式恢复精确且唯一；补齐已捕获FAQ进入实际提取输入、准入和规范事实的链路。保留严格原文校验，不用诊断元数据替Writer补事实。
2. **按子问分配证据、允许合理条件推论**：修正任务／事实窗口错配；针对权限范围、许可与义务、CPU计费建立明确任务合同。请求假设无需官方证明，已有证据支持的合理否定和澄清不应被选证器拒绝。
3. **联合调度写作与审核预算**：把完整父题设、建议、所选事实及最终QA一起预留；显式区分缺证、容量不足与未发送。加强不同动作／上限的原子拆分，修正正文分区文案和审核状态。
4. **评估按复杂度选择流程**：简单事实和澄清可先测试轻量路线，多产品比较、冲突消解及策略判断再调用相应角色。本轮single是诊断CLI，尚未成为生产路由；新的人审盲样本及重复实验通过后再决定，不据一次已曝光八题切换架构。

暂不进行 Agentic RL。先保留成功、失败和合理拒答轨迹，消除错误奖励及不一致审核，再决定是否需要训练。
