# Agent 提示词与事实覆盖：实施与效果记录

日期：2026-10-07。基线：`40e0f520b7923959c791fb197b741cfdff713200`。

## 1. 本轮完成的范围

按 Writer → Comparator → Collector → 调用追踪与评测的顺序实施。

### Writer：让实际调用使用统一模板

- Markdown 初稿、分段生成、章节修复三个真实入口接入 `WriterPromptBuilder`，测试直接拦截传输参数验证接线。
- 保留研究深度预算、中文标题、决策背景、出版修复、分段约束、来源快照校验。
- 极简模式要求紧凑分析；保留小数和单位；区分“本次没有采集到”和“官方没有披露”。
- 结构化报告路径保留原有模板。本轮没有迁移所有 Agent 的提示词。

### Comparator：允许明确停止比较

- 新增维度判定：可比、证据不足、条件不一致而不可比，并保存理由、适用场景、取舍、缺口和引用。
- 缺口状态的 `winner` 为空，不再被页面数量投票覆盖成赢家。旧矩阵仍可读取。
- 代码独立校验当前 Evidence View、来源归属、证据置信度、各产品的支持事实与可比条件。
- 价格比较要求对应价格事实，以及货币单位、市场、计费周期和税费范围；条件缺失时暂缓判定，已知条件不同则标记不可比。
- 最终代码判定后同步摘要及被否决理由，避免 Writer 接收到相互矛盾的状态。

### Collector：HTTP 成功不等于事实齐全

- 将缺失意图、定向补采提示和剩余轮数传给 ReAct。
- 复用已抓取响应做提取、证据准入和覆盖检查，不为反馈重复发起 HTTP 请求。
- 有抓取页面但事实覆盖未通过时，不接受提前完成；预算耗尽后保留候选与缺口，候选仍需流水线审核。
- 两个价格提取分支都排除运费、最低账单门槛等金额，并保留同一上下文中的合法产品价格。
- 价格覆盖要求页面、候选和证据正确绑定，且当前页面存在独立提取出的产品或套餐价格行。

### 调用追踪

- 原生 JSON/text 调用记录 `prompt_id`、版本、系统与 Schema 指纹、完整输入指纹。
- 本轮涉及的模板标记版本 2；未纳入版本管理的调用标记 `unversioned`。
- 复用现有调用预算和日志，不额外输出凭据。指纹用于定位实际调用变化，不代表完整语义模板版本。

## 3. 真实模型对照

使用固定合成诊断数据，未读取业务知识库，未创建业务报告。共两轮、48 次模型调用；下表为最终轮 12 个案例、24 次调用。实际配置模型为 `deepseek-flash`，温度 0，单次输出上限 1400 tokens，不使用备用提供商或自动重试。

旧提示词从基线提交的实际调用表达式读取；新提示词使用当前生产构造器或实际调用表达式。每个案例的两个版本使用相同证据、模型、温度和输出上限。Comparator 的输出 Schema、Collector 的覆盖反馈也一并改变，因此结果不能单独归因于文字措辞。

| 检查项 | 基线 | 新版本 |
| --- | --- | --- |
| Comparator 无依据赢家判定数，8 个案例 | 4 | 0 |
| Comparator 正确区分状态，8 个案例 | 旧格式不提供状态字段 | 8/8 |
| 唯一可比案例同时引用两产品证据 | 否 | 是 |
| Writer 保留指定数值、合法引用、中文标题，2 个案例 | 2/2 | 2/2 |
| Collector 选择继续采集且有有效动作目标，2 个案例 | 2/2 | 2/2 |

Comparator 案例包含市场不同、周期不同、缺价格、产品不明确、同条件可比、缺税费范围、弱搜索证据、网页指令注入。Writer 与 Collector 的检查只覆盖小数、引用、标题和采集动作等局部行为。

第一轮发现缺税费仍判赢家，随后强化税费规则并重测。最终 24 条调用成功；保存结果的全部输入指纹与当前提示词匹配，并用修正后的评分器离线重评。缺口状态不能用 `tie` 冒充空赢家，采集动作不能缺 URL 或查询。

## 4. 当前结论与未验收事项

本轮达到了提示词接线、缺证据时暂缓比较、定向补采反馈和可追溯调用的工程目标。固定诊断中的 Comparator 行为改善；Writer、Collector 的局部指标与基线持平，不能宣称全流程效果显著提升。

以下仍未通过本轮验收：

- 真实产品从发现竞品、联网补采到完整报告的端到端质量与及时性。
- 动态价格页面的浏览器渲染、计费开关和席位矩阵抓取。本轮修复了提取及覆盖判定，没有解决所有动态页面采集。
- 全报告事实忠实性、所有句子的引用完整性、中文表达质量和产品经理决策价值。
- 真实业务样本上的 RAG 召回与精排效果。合成诊断不能证明 RAG 合格。
- Planner、Analyzer、Reflector 等其余角色的统一模板迁移，以及完整 Prompt 版本治理。

## 5. 建议下一步

1. 固定一组经人审的真实产品任务，覆盖实物产品、SaaS、产品名歧义和动态价格；用相同任务比较报告事实、引用和可行动建议。
2. 优先补齐动态定价采集与价格条件矩阵，避免模型反复补采仍拿不到关键事实。
3. 用实际调用追踪定位重复证据和过长上下文，压缩输入后继续检查暂缓判定与引用，争取降低本轮新增成本。
