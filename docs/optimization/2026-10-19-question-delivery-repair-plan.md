## 任务一：当前正文的条件窗口和准入

主要文件：`backend/packages/tools/deepseek_fetch.py`、`evidence_fetch.py`、`backend/packages/research/extraction/semantic.py`，以及来源结构、提取和 Collector 交付测试。

1. 先增加失败测试：匿名转义 Markdown 标题、父级权限、相邻例外、同名标题、围栏内伪标题、错误哈希、不同抓取表示、缺失 FAQ。
2. 在当前正文的原始字符坐标上记录可验证的表示结构；若支持供应商转义 Markdown，必须明确其表示类型，与 DOM 来源路径分开，不修改原始正文、不伪造源站状态或最终 URL。
3. 条件按有身份的父级和局部完整段归属；不能将别的段落条件灌入每条事实，也不能因缩窗遗漏父级约束、否定或完整例外组。无法安全定位则保留缺口。
4. 上一次 HTML 抓取的结构诊断单独留档，不能借给当前 Markdown 事实充当已绑定条件。当前缺失的 FAQ 仍需报告缺失，不能从旧元数据补答案。
5. 测试必须验证原句 → 准入 → 规范事实 → SNAP → Writer 可见视图，不能只断言提取非空。重放旧 guests 正文，保留定价未捕获的诚实缺口。

## 任务二：逐题公平选择、语义回答和例外闭包

主要文件：`backend/packages/agents/writer/question_retrieval.py`、`dimension_writer.py`、`literal_non_operation.py`、`answer_resolution.py` 及确需修改的主张审核入口。

1. 先用匿名两题复现第一题被挤占、中文澄清及非操作事实被错误要求操作绑定。
2. 在既有 8 条 / 14000 bytes 预算内逐题安排核心证据和必要条件；无法容纳时明确逐题缺口，不以空的例外列表宣称闭包完整。冗余判断不能只按粗分支类别早停：同类别但角色、条件或例外不同的第四条原句仍须保留，原文、值与限定条件完全相同的重复才可安全合并派送。
3. 有操作陈述必须明确绑定操作；中文非操作答复和澄清通过已有受约束语义审核核对事实及引用，不因同一事实另有操作候选而被一刀切删除。仍阻止错角色、错对象、极性反转、无依据扩写和错引。
4. 例外需求由问题和最终主张共同确定：写入登录等附带主张时，必须带齐相应例外，或删除不必要的附带主张。不能仅因问题没问登录便丢掉已写主张的 SSO / 恢复等约束。
5. 覆盖中文改写、否定、澄清、多分支例外及引用篡改，验证实际 Writer 和最终保存的逐题记录一致。

最终 QA 仅对合格澄清消除状态误阻：要求 `partial / clarification / depends / v2`，实际发布且精确绑定的源规则、完整必要澄清、全部回答守卫重放通过，正文保留未变的保存答案。普通 partial、缺绑定或源规则、改稿、缺 core 或例外仍阻断；合格澄清保持局部交付身份，不伪装完整直接回答。

诊断补充：完整 SNAP 也无法弥补“主张依赖 value 旁段、例外却按 quote 匹配”的锚点错位。优先采用明确的完整源片段绑定，复用现有逐主张语义审核；绑定必须能在当前事实原文中重新验证，不能以中文关键词相似代替支持。若需要可选持久化字段，应兼容旧记录并验证接口变化，不为维持接口字节一致而隐藏必要的审计信息。

## 任务三：金额组成和研究范围门禁

主要文件：`backend/packages/orchestrator/answer_context.py`、`backend/packages/research/evidence/monetary.py`、`backend/packages/agents/reflector` / QA 实际范围判定入口及对应测试。

1. 匿名复现用量单价、账户最低费用、同一行多个金额，以及单产品问答被多竞品矩阵门禁阻断。
2. 原文计费组成只支持其自身货币、单位、周期、套餐和条件，不能冒充购买总价；缺货币、错单位、错套餐、错引用、无依据含税或换算仍须阻断。多个金额各自保留诊断身份，不能同一行去重掩盖第二个错误。
3. 用实际任务范围决定哪些比较门禁适用：明确的单产品逐题问答不要求多竞品矩阵；有比较任务或多竞品时仍检查缺列、共同口径和缺证。不得全面降级阻断或跳过 QA。
4. 跑实际 Writer → QA 证据 → 最终 QA 离线链路及匿名反例，不把模拟模型肯定答复当作独立语义验收。

诊断补充：匿名真链已复现相同的五个阻断。金额采用原文组件的可重放绑定，拒绝仅以“数字在来源中出现”放行；派生组件若不能证明算式，则保留费率与具体不足答复。范围由现有 brief / plan 判断，单产品但要求与目标产品比较或完整分析时仍保守使用相应门禁。Reflector 要看到实际问题，且最终门禁复核适用性，不能仅靠提示词期待模型改变判断。
