## 1. 本阶段解决的问题

原流水线的主要风险是各 Agent 读取的资料可能来自不同版本，以及证据更正后仍复用旧分析。运行级快照保存产品、市场、事实值、原文、来源时间与资料版本；Agent 按职责取得片段，并在写入结果前检查依赖。

阶段检查使用当前已接受的分析快照；最终报告引用审计回读报告的原生成快照，再检查来源当前是否仍有效。保留旧报告时保留其原生产身份，不能因为一次新 Writer 调用失败而将它登记为新证据的产物。

## 4. 当前最值得继续优化的方向

本阶段已补齐更正闭环：未冻结的新材料阻止旧提交，原报告引用保留审计身份，未变分支记录原生产者与当前验证。章节依赖不完整时保守重写整份 Writer，不宣称只重写章节已完成。

下一阶段优先**用真实调研题评测检索**。现有基准只有 14 条合成查询，使用 hash embedding / reranker。它只能作为离线契约回归，不能证明中文语义召回质量。至少 50 条人工标注查询应覆盖消费电子、SaaS、生活服务等产品的同类竞品发现，以及完整型号、市场、套餐、来源日期、模糊或不存在的产品、无答案和越界拒绝。

真实 embedding / reranker 应在独立新索引上与关键词基线对比；同时检查答案原文支持、陈旧事实误用、来源质量、延迟和成本。检索质量达标后，再评估扩大跨运行报告复用与 Agent 训练的收益。
