# RAG 离线质量基础交付

## 本轮范围

用户确认先做离线评测，允许采集官方公开资料。完成数据合同、首批固定资料、结构清洗与分块，以及共同资料池的关键词诊断入口。评测不调用外部模型、不安装依赖、不下载模型权重；现有文档、历史快照与真实运行资料没有自动重切或升级。

## 已实现

1. **可核对的数据与标签。** 保存型号、市场、来源角色、源日期、抓取日期、URL、正文 SHA-256 与引用字符位置。拒绝错型号、错市场、未来证据、无效引用，以及把未标注误当无答案。正式入口只接受 `evaluation + reviewed`；候选结果使用显式 `candidate-diagnostic`。
2. **保留正文结构。** 清理导航和隐藏旧内容；保留标题路径、表头、caption 和邻接条件 / 脚注。原子表格超字符预算时保留正文并标记 overflow；缺表头、合并单元格和无结构输入记录缺口。中文连续句子与英文小数有回归。
3. **可复现的离线检索诊断。** 一次入库、所有问题共用资料池；可信空间、项目、型号、市场、来源角色和研究日限制在 SQL 召回前生效。保留原查询，不根据答案补词；不同研究日使用独立查询缓存。文档命中指标与实际引用片段覆盖分别记录。
4. **评估接口与运行记录。** 按品类、文字类型、市场、产品和日期分组，记录索引耗时、检索 p50 / p95、SQLite 大小及进程峰值 RSS。准备带来源与位置的 Ragas 输入；没有生成回答时 `response=null`，事实、澄清和模型评分保持未执行。

## 当前最值得优化的问题

现有 FTS 将原问题的所有词组成必需匹配条件，中文连续文本还会拆成二字词。调研问题往往包含来源没有逐字出现的问法、限制词；英文官方节选也无法覆盖中文查询词。当前入口保留原查询，因而能够暴露召回不足。下一步应先处理关键词召回和中英文匹配，再验证融合与精排；不要通过把标准答案拼进查询提高分数。

资料本身也不足：多为短节选，13 份没有公开源日期，城市生活服务覆盖不足。结构回放通过不等于完整网页或动态价格已经验收；当前表格只关联一个紧邻前段和一个紧邻后段，不保证任意远距离脚注或复杂布局。固定资料池要求每条 source 对应独立的活跃文档；同正文导致去重碰撞、或同 URL 不同快照导致旧源归档时，评测会明确拒绝，而不是继续计算有歧义的指标。若要评测多快照，需要另行设计版本资料池。

2. 用独立调参资料改进关键词召回与跨语言匹配，保留权限、市场、角色和日期限制，比较引用覆盖及无答案噪声；正式验收标签不用于调参。
3. 确定本地模型或现有 HTTP 服务后，建立独立语义索引，比较 sparse、dense、RRF、RRF + 真实精排。hash / 降级输出只用于合同验证。
4. 有真实回答与人审参考后，再抽样运行 Ragas，核对引用与事实；不把模型评分加入每次生成的同步门禁。微调、蒸馏和 RL 等待足够的失败样本与基线后决定。

HTTP Qdrant、完整联网研究流水线及 PostgreSQL RLS 的外部条件仍未在本轮验收。当前无需用户安装或运行命令。

## 复现入口

在项目根目录使用已有 Python 环境，诊断明确禁用环境文件；程序只创建临时 SQLite。

```bash
COMPETISCOPE_LOAD_ENV_FILES=0 PYTHONPATH=backend \
  ../plan_a/.venv/bin/python -m packages.knowledge.product_benchmark \
  --mode candidate-diagnostic --output /tmp/product-research-diagnostic.json
```

省略 `--mode candidate-diagnostic` 即正式入口；当前因人审标签为 0 返回 `not_ready`、退出码 2，不写正式评测结果。输出包含计时、资源与临时 ID，因此不要求整份 JSON 字节一致；比较时使用稳定 source ID、指标及引用覆盖。
