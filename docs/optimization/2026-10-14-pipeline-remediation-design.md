# 主流水线五项修复设计

日期：2026-10-14。用户已明确批准按照上一轮审计提出的五项顺序修复。该授权覆盖实施、测试、既有本机模型使用和真实 DeepSeek 流程验证，不重复请求方案确认。沿用当前隔离工作树 `codex/pastoral-desktop` 和交付目录，保留已有未提交工作。

## 设计选择

采用现有架构内的逐项修复。整体重写会扩大回归范围；只放宽门禁会保留错误事实和被跳过的 Agent。实施以原文、阶段产物和用户操作的实际闭环为边界。

1. **事实来源**：任务市场、问题中的角色/套餐及输出要求属于查询上下文。正文提取出的市场、价格条件及权限限制属于证据事实。KB canonical 元数据不得把请求条件补成事实；未知和相冲突条件保持未知/冲突。覆盖新入库与历史 canonical 文档，不直接修改生产资料库。
2. **阶段预算**：保持现有任务总 token/call 上限，为 Collector、Analyst、Comparator、Reflector、Writer、QA 分配可恢复的阶段额度。停止尚未必要的补采和盲重试，保留分析阶段首次执行机会。实际模型成功、确定性回退、缺证跳过和失败分别记录，界面可识别。总额度确实不足时明确给出预算缺口，不假称模型分析完成。
3. **产物消费**：新维度 Writer 接收经过快照/依赖校验的分析、比较判定、决策与反思约束；结论不能越过证据状态。操作观察包含显式 operation、来源 fact/observation 身份、对象、角色、effect 及条件引用，服务端核对后投影。局部重做保留未受影响的已审核段落，修改段仍逐条审核；禁止直接从中文关键词推导唯一操作或复用未审核的新正文。
4. **生产语义 RAG**：复用已下载的本地多语模型与现有 Qdrant 版本/作用域合同。Provider 明确启用后，捕获全文建立对应向量索引，Collector 使用配置的 sparse/hybrid；Agent tool 与 HTTP API 使用一致的可选精排 Provider。缺权重/索引时记录降级，hash 不冒称语义模型。默认本机持久化 Qdrant 验证；HTTP 集群恢复仍单独验收。
5. **验收与用户闭环**：补独立候选评测集及审核清单，不把模型核验标作人审。前端接人工正文修订、重验、新版本；导出通过授权的下载 API 获取服务器产物，包含认证与错误处理；Search/Crawl 携带项目作用域。运行列表、详情、trace/stream、KB、revision、用户资料导入都采用服务端身份和 workspace 授权。保持本地开发兼容，拒绝跨工作区读取和写入。正式多租户测试在隔离应用/临时存储完成。

## 验收条件

- 缺市场报价在入库、快照、Writer/QA 前后都不能变成指定地区的当前价；已知异市场不被请求市场覆盖。
- 固定四家标准任务在原 200000 token/60调用限制下，证据充足时各 Analyst 有实际模型请求；比较、反思有执行机会，Writer/QA额度不被上游吃光。
- 改变有效上游分析/比较/反思产物会改变写作输入；过期 hash、越界事实和伪造操作绑定拒绝。
- 本地模型生产入口能够对固定中文自然语言问题执行索引→hybrid→可选精排→Collector warm start；记录 Provider、版本、索引与消费依赖。
- 人工修订和下载在前后端合同测试及必要浏览器验证中闭环；跨工作区 run 接口拒绝；未审核评测样本不能使正式评测通过。
- 全量后端、前端测试与编译通过；真实流程保留原始草稿和失败诊断，交付结论依据真实语义覆盖，禁止以 completed/引用合法/小池召回100%代替准确率。
