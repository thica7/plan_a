# 单谓词生成、逐子句审核与失败任务补交

本轮目标是让实际已采证据进入各子任务的最终答案，重点检查 Trello、1Password 和 Cloudflare CPU 计费。按任务实验仍需同时开启 `WRITER_TASK_EXECUTION_ENABLED=1` 和 `WRITER_QUESTION_ATOMIC_ENABLED=1`，两个开关默认均关闭。

**最终结论：执行与审核机制完成本轮修复，报告内容仍未达到交付标准。** 最终四家固定页真实模型复验为2/8原题完整、14/22分支完整，文本加证据报告1/4、严格系统QA0/4；CPU补交已真正发出，但模型仍合写运行时限制，未产生合格的CPU正文。不能称Trello和1Password漏答已全面解决。

## 实际改动

- 新执行增加内部 `task_clause_contract=single-predicate-clauses-v1`。GEN 每次只返回一个服务器指定任务的一个 atom；问题身份由服务器补入，不接受模型自由改写父题状态或生成其他任务。
- 服务器按有界标点、连接词生成完整子句清单，审核须逐项返回身份、作用、任务匹配和精确支持。条件与例外继续保留；只有一个实质目标断言才可发表。不能仅凭模型自报 `predicate_count=1` 放行。
- 同一完整条件中的 AND 前提跨子句保留，条件结束后出现的新能力不能继续伪装成条件。该识别仍是有限规则与模型审核的组合，不是一般自然语言逻辑证明器。
- 失败反馈保留具体原因。有效 SELECT 可在相同运行、快照、消费记录与任务下认证复用一次，只补 GEN 和 REVIEW。已成功任务，包括 capability 回退任务，不接受补交覆盖；不伪造新的 SELECT 调用。
- ANSWER 可选引用统一为已审核 claim，完整 quote 内联保留。移除把 quote alias 混作 claim 引用的诱因，不清洗或改写历史原始响应。
- 没有内部标记的 V1/V2/V3、旧 SYSTEM、原始失败及回放身份保留。带本轮新标记的中间实验记录按各自冻结源码验证，不能拿新解释器给旧失败补成功身份；公开 `task-outcomes-v1`、API 类型和前端不变。

## 补交没有实际派送的已确认根因

对真实history、snapshot和认证SELECT进行只读重建：CF清缓存补交14749 bytes、CPU补交14259 bytes，均超14000字节上限。repair预检记录admitted=true，call却在wire长度检查直接返回None，未生成补交LLM span。省去可选失败raw诊断后，完整问题和证据仍可入窗；原始失败响应及hash保留在原trace，不改来源资料。

Trello四项补交未超窗，原因确为`reserved_for_delivery`：当时已用123097 token，保护最终回答和QA的103897 token后仅余13006，单个GEN需要17162–18737。不是CF同一个问题，也不是已证实的refresh预算矛盾；不能用抬高预算掩盖。

派送修复使用独立dispatchfix目录，前两轮失败与原样报告全部保留。新合同仅在完整补交wire超真实`min(14000, use.max_bytes)`时省去可选失败raw诊断，原因码、真实前次span及哈希、任务全文、完整所选quote和复用证书继续保留。原始失败raw仍在原trace中；已经入窗的反馈保持原样。

预检与派送现在共用完整UTF-8 wire计量。压缩后仍超窗时记录本地`question_task_context_rejected`，任务明确延期，并将本地证明绑定进可重建receipt；不会创建虚假LLM派送记录。内部`TaskDecisionContext.max_user_bytes`从真实消费记录传递，8k等较小上限也按相同规则重建。没有新增公开API、提高14000上限或改Trello保护额度。

该增量已通过独立规格293项、独立质量414项验证；作者专项417项通过、Ruff新增0。标准工具新导出API schema与TypeScript类型逐字节一致。实际四家最终内容结果在同一冻结源码下另验，不能由这些机制测试推定通过。

## 下一步应优先做什么

1. 给每个任务明确一个语义目标及状态前提，例如“确认后持续访问”与“邀请动作”分开；先验证选中的原句确实回答该目标，再写作。已经采到的access句没有进入双vault答案，继续补更多页面不能直接解决这一交付缺口。
2. 将失败码转成具体、短的重写指导；核对每个待发表子句究竟是条件还是独立定义／操作。CPU已有明确目标仍两次复写整段，纯JSON格式与有限能力词规则没有解决一般语义拆分。
3. 从同一组实际已发表、逐项绑定的结论计算正文、问答和QA状态，单列必要澄清与产品事实未确认；先解决Trello正文有答案但状态unknown、Bitwarden合理澄清仍被阻断，再决定是否扩大实验入口。
4. 单独优化保护预算与任务窗口，保留硬额度；Trello补交当前确实受保护额度限制。仍保持本轮实验默认关闭，不把严格QA0/4包装成生产验收通过。

## 范围与限制

完整原题覆盖、精确引用支持、主张原子性和系统 QA 分开判断。任务正常结束、JSON 格式正确、重建成功或审核模型返回 supported，都不能单独证明报告达到交付标准。缺证任务应保留简短局部答复及缺项，不能输出编造金额或无证权限。

本轮不执行 Docker、不训练模型，不改全局模型预算或生产默认开关。固定页面回放不能证明实时联网质量、生产语义 RAG、跨实例恢复或并发容量；这些需要各自验收。
