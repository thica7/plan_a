# DeepSeek 搜索接入与真实验收记录

日期：2026-10-02。分支：`codex/pastoral-desktop`。

## 结论

DeepSeek 原生搜索已接入，真实搜索、网页正文抓取、预算记账、来源追踪及自动竞品发现均已验证。完整自动调研到可发布报告仍未通过：最终任务缺少两个竞品的有效功能证据，被采集质量检查阻断，报告为空。

自动化回归通过不能代替真实报告验收。本记录保留两者的不同结果。

## 本轮完成

1. 新增统一搜索接口和 DeepSeek 客户端；竞品发现、采集、RAG 补充、企业证据缺口补采及 smoke 使用同一个客户端工厂。保留 Perplexity 兼容配置。
2. 主报告模型继续使用现有 Chat Completions；搜索使用官方 Anthropic Messages 原生工具。仅接受 `web_search_tool_result` 中的结构化 URL，不将模型自由正文中的链接冒充搜索结果。
3. 网页正文由应用现有 HTTP / 高级抓取能力获取，再经过身份、事实、来源和引用检查。DeepSeek 搜索工具本身没有替代正文证据流程。
4. 搜索与生成共用运行 token、调用次数及费用预算；独立 smoke 和项目补采也有预算。请求取消或未知 usage 保守结算；预算拒绝发生在发送请求之前。费用使用项目配置价格估算。
5. 运行内成功查询缓存五分钟，相同查询并发去重，过滤条件隔离。证据刷新绕过并更新缓存；命中不重复计费。失败结果不缓存。
6. 真实 usage、缓存 token 和服务器搜索次数写入 trace；DeepSeek 候选保留独立 provider 标签，低置信候选继续受高级抓取门槛限制。
7. 只在已确认产品身份后提高用户 URL 的采集优先级：可信登记来源 400 > 已确认用户 URL 301 > DeepSeek / Perplexity 搜索候选 300。优先级不会改变来源 authority 或事实准入。
8. 修复实际暴露的两个旧问题：极简报告的无效“产品机会”段落改为明确的待验证假设，再执行严格报告校验；非 AI 产品分析保留通用功能节点，避免被编码工具分类覆盖。旧记录的空 normalized_fields 兼容读取。

## 官方接口依据

- [DeepSeek 官方搜索实现](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/web/web-search-deepseek/src/provider.ts)：固定官方端点 `https://api.deepseek.com/anthropic/v1/messages`，工具类型 `web_search_20250305`。
- [官方 HTTP 抓取说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/web/web-fetch-http/README.md)：web_fetch 由应用 HTTP provider 执行。
- [Anthropic 兼容接口说明](https://api-docs.deepseek.com/guides/anthropic_api/)。

本地使用 `WEB_SEARCH_PROVIDER=deepseek`、`DEEPSEEK_SEARCH_MODEL=deepseek-flash`、输出上限 1024、原生搜索最多一次。凭据仅保存在 ignored 配置中；本记录不含密钥。

### 能力边界

- 域名允许/排除在客户端强制检查；国家、语言和时效是搜索偏好，不能保证供应商完全遵守。trace 明确标记这一限制。
- 原生搜索会注入供应商内部上下文，不能事前准确估算输入 token。当前每次搜索预留 16384 输入 token 加请求长度，收到 usage 后按实际值结算；超过预估会阻止后续超预算请求，但不能保证供应商端硬账单封顶。
- 不自动重试搜索请求，避免超时后重复收费。运行缓存不会跨任务永久复用过时结果。

## 真实联网验证

### 搜索和正文抓取

- 实际账户探测返回 HTTP 200、10 条结构化候选、1 次服务器搜索；记录到 input 9977、cache read 256、output 838。总输入按三类输入相加结算。
- 搜索 smoke 返回 3 条候选，约 4.68 秒；其中包含任天堂规格页。
- 任天堂规格页正文抓取 HTTP 200、12926 字符、约 0.38 秒，正文哈希 `97550cf00cf6cc09`。
- 无 Perplexity 凭据时，运行配置和健康检查均认定 DeepSeek 搜索就绪。

## 当前问题与证据

### P0：采集尚未完成产品通用化

- 社区补采 feature 模板仍固定包含 context window、agent mode、developer workflow；真实硬件任务 trace 出现了这些不适用查询。
- 多次正文包含荷兰语、俄语、德语，现有通用功能抽取主要依赖中英文动词；搜索语言偏好并非硬限制。
- 通用事实抽取要求完整产品名称出现在能力动词前。产品别名、变体、对比文章和规格表会漏提；ASUS ROG Ally、ROG Ally、ROG Xbox Ally、ROG Ally X 也不能直接视为同一型号。
- 极简分支每主体只有一次搜索、三次抓取。低相关候选和正文噪声先耗尽预算，后续官方补采无法继续。直接增加轮次会提高费用，不能保证增加事实。
- 任天堂域名虽由用户明确提供并完成身份确认，现有通用来源适配仍标为 third_party。身份确认、域名归属、官方来源和事实可信度需要分别核验。

### P0：失败任务的用户结果不充分

有效证据不足时当前终态是 failed、报告为空。门禁正确阻止无依据发布，但用户缺少可读研究草稿、缺口说明和“补这一项”的操作。需保留发布标准，同时让已有结果可见。

### P1：事实对齐和准确性仍待提高

通用 capability_1…6 是抽取顺序，不是跨产品同一指标。规格页的屏幕、存储和电池片段存在交叠；导航及广告也可能污染正文。不能据不对称证据给出明确性能胜负，下一步需要同一口径字段和可回查的证据位置。

### P1：成本和修复效果需量化

最终功能单维度任务已计 89941 token。缓存及预算已实施，仍需要缩短无效查询、只补真实缺口、压缩来源片段，记录每次补采新增了多少可用事实。历史报告可复用研究计划、事实索引和待刷新列表；价格、型号、状态等应按时间与来源重新验证。

### 运行环境

搜索与主模型凭据就绪，但整体 health 仍为 error：旧 Temporal 切流检查要求 temporal，而当前实际路由为 langgraph；本地 Temporal 服务也未连接。没有备用模型凭据。不能宣称所有生产就绪检查通过。

## 下一阶段建议及验收口径

1. **先修采集。** 按产品类别生成查询；区分型号与别名；先验证官方来源及相关语言；清理正文并抽取带原文位置的指标。采集预算优先保留定向补缺口机会。以本轮三个产品做离线固定样本回放，再做一次真实报告验收。要求三个主体都有有效来源、字段对齐、引用可回查。
2. **补草稿和定向修复。** 证据不足也展示已取得结果与明确缺口；半人工允许替换竞品、补 URL、确认型号。打回重做只修指定主体 / 字段，保留有效证据和章节。分别记录草稿状态与可发布状态。
3. **再优化 token 和历史复用。** 对缺口实施有上限的增量检索；复用有来源、有时间、有权限的历史事实；失效内容进入刷新队列。用调用数、token、事实增量、报告通过率衡量收益。
4. **RL 放在可复现评测之后。** 先建立非 AI 产品、别名冲突、过期信息、抓取失败等固定案例和人工标注；记录工具轨迹及最终引用质量，再判断是否需要训练。当前不具备宣称训练有效的证据。

本轮没有验收详细多维度、半人工真实交互、跨历史报告完整复用或 RL 训练。前端像素视觉保持既有实现，本轮没有把构建通过当作视觉验收。
