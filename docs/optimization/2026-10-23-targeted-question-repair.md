# 子问定向选证、局部重写与最终 QA 重核

日期：2026-10-23。基线 `e0f6c5d`；分支 `codex/pastoral-desktop`。

**结论：实现、回归及两轮真实阶段测试已完成，报告仍未达到完整交付标准。最终同八题严格完成4题，另4题仍不完整；Trello 还存在可见断言超出所选支持的问题。** 不能把工程测试通过或引用身份合法等同于报告准确。

## 本轮改动

1. **完整规则提案**：Collector 从当前提取窗内提议与原问有关的完整原段或完整小节，重新经过原有来源、原文坐标、条件和入库准入。无可靠标题结构时完整正文上限800字符；有可验证结构时完整小节上限1600字符。父规则与子例外保留在一起，跨窗、过长或边界不明则拒绝。导航和疑问句不能作为规则提案；坏 disclosure、表格和标题验证不能通过此路径恢复。
2. **子问局部修复**：Writer 仅对有具体审核缺口的子问，按缺失前提重选当前证据、生成最多4个新原子。已通过的原子与未受影响答案保留，新原子仍须通过逐条引用和独立审核。最多一轮，新增调用最多5次，包含最多2批主张审核和2次答案复核；原写作1600输出上限与共享预算不变。格式错误、传输失败和泛化的“未选答案”不会触发盲重试。
3. **逐项对象覆盖**：明确要求分别判断的命名对象须各有动作结论；背景中的 A/B 不能代替请求对象，也不能只回答 A 却将整题标记完成。这里只是有限对象/动作守卫，正反结论是否成立仍须语义审核。
4. **计费事实引用**：服务器不足报价答复只有在同一当前快照已有正式审核主张和精确支持时，才发表对应 CPU 时间计费前提。Standard 表格必须重验模式、CPU 列、单位、表头和脚注；缺少输入仍不计算完整账单。没有合法引用时只要求补充 CPU 等输入，不发表无引用产品短句。最终 QA 按相同主张重放。
5. **最终 QA 时点**：对可明确映射到原问题的历史 Reflector finding，以当前正文、已审核答案和精确支持重新判断，保存问题、主张、支持摘要、快照及产物身份收据。混合来源/矩阵问题、真实引用失败、无法映射或预算不足均保留；不因 `answered` 标签自动消除 blocker。原反思历史保留。

## 首轮真实测试发现的传递故障

首轮四家输出保留在 `live-*-first/`，没有覆盖或拼接最好答案。独立严格审核为1题通过、3题部分、4题未完成；安全拒绝编造报价单独计量，不作为整题完整通过。

- Bitwarden 的实际 Writer 窗口含完整事实，但没有可选 `s` 引用；模型使用不存在的引用后所有原子被拒绝。代码原先先填事实再加引用，容量耗尽后会形成无法引用的输入。修复为每个可保留事实先预留完整合法支持，再装额外事实与引用；完整原文和条件不截短。
- 1Password 已有合法私人库规则，但在装窗前遗漏；缺失谓词的检索焦点现在先参与完整候选排序，再做预算选择。检索提示来自失败诊断，不被当作证据。
- Trello 的部分修复审核已经返回 supported，但将压缩后的 `text_ref` 对象复制到严格字符串字段 `claim_span`，导致审核无效。审核目标主张和需原文回写的字段现在保持字面字符串；未知引用对象仍被严格拒绝。
- 单独估算修复元数据与资料窗口可能浪费共享字符串释放的实际空间，因此增加最多两次本地回填。每次重新验证完整合并后的14KB和实际 canonical 支持，超限时保留原包。此机制不保证所有大段都装得下：真实 Trello 的另一完整候选跨过容量阈值时仍被拒绝，不能以截断前提换取覆盖。
- Cloudflare 首轮 Writer 单次请求45秒超时。传输失败不伪装成语义不支持，也不增加自动重试；首次记录保留。

这些修复均先补失败回归。复测仍使用同八题，不能称为新增独立样本或单因素实验。

一项既有容量测试同步调整了明确合同：六条带末尾空格的859字符原文，连同858字符的完整合法支持，需要约17.6KB；旧14KB能装六条是因为没有可用支持。测试现在同时验证14KB下明确的整条省略及保留引用、18KB测试窗口下六条全部保留；两种情况都核对原文、值、条件和快照完全不变。**生产默认14KB没有增加**，没有通过清理原始空格或放松引用匹配挤进窗口。

## 剩余问题与下一优先级

1. **先做按子问分配的紧凑证据卡**：完整原文、来源条件和例外只保存一份，以明确身份供各子问选用。Trello虽然已有逐板和计费资料，失败诊断、重复父段和操作字段仍挤占窗口；完整候选回填会达到16820B而被14KB正确拒绝。不能靠增加提示词或直接截条件解决。
2. **让局部修复计划匹配剩余预算与原子数**：Trello第二轮同一次修复返回5个原子，超过4个合同后整体拒绝，没有审核或发表。当前错误统一记为 generation unavailable，需区分输出超界与传输失败；按缺失子问优先级生成独立原子，不能静默取前4或放松原子性。下载与导出已有正确支持，但复合写法被原子审核拒绝。
3. **修完整断言审核和问题级QA归属**：Trello“所给页面未记载强制义务”超出选中单句能证明的范围；分类说明也不能代替完整逐板/计费结论。另一方面，Bitwarden两题的最终答案和澄清均通过逐题重放，却因 `audit.gaps` 残留全局 `question_core_context_budget_exceeded` 被添加假 coverage blocker。应按具体问题身份处理纯请求澄清与事实/例外缺口，不能全局忽略gap。
4. **补齐计费规则到正式主张的正向链**：Cloudflare快照已有完整Standard CPU行，但没有进入Writer/修复实际派送的事实ID；现在不会发表无引用CPU短句，正向规则仍未生成，应先修选证与传递。1Password无合格公开报价来源，不能杜撰报价性质或销售路径。需要正确引用和适用资料准入，保持金额未知。

本轮没有将这些问题自动标记完成，不训练模型。生产稠密RAG、新抓取和独立未曝光样本仍需另行验收。
