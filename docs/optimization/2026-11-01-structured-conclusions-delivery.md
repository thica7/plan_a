# 数量上限、计费缺项与统一结论版本

按[实施计划](2026-11-01-structured-conclusions-plan.md)，本轮先处理两个有限关系：数量超限否定、计费输入不足。暂不训练模型，Docker 留给另一台电脑；复用现有存储和实验开关。

两类结构化结论已在真实模型回放中交付并通过同版本核验，**整体报告仍未达到交付标准**：8 原题 3 完整、4 部分、1 失败，严格系统 QA 为 0/4。结果与失败均保留。

任务始于 2026-11-01，验收续至 2026-11-02，文件名保留起始日期；原始日志的 UTC 时间不改写。

## 要解决的交付问题

上轮 Cloudflare 已选中正确 CPU 计价原文，但自由写作仍复制费率和运行时限制，所需计费关系未发表。Bitwarden 已有受支持的容量否定，持久化正文、观察区和后续认证投影仍有差异。单纯再加提示词不能保证三处消费同一结论。

本轮在已有 `selected-task-atoms-v3`、`semantic-target-clauses-v2` 外增加内部 `structured-conclusions-v1`。两个 Writer 实验开关仍默认关闭；显式启用后的新鲜 scope 才采用新合同。已产生派送或 receipt 的旧记录保留自己的合同身份，不用当前实现改写历史结果。

## 有限生成与独立验证

```text
实际 SELECT 绑定
→ 服务器有限候选（来源事实、请求前提分别标记）
→ 模型选择 candidate_ref，或明确拒选
→ 独立 source REVIEW 核完整所选原文、条件和范围
→ 服务器受限推导
→ 价格／澄清处理结束后冻结 ConclusionSet
→ 同一版本生成正文、问题答案与最终 QA 上下文
```

模型不能提交自由段落、任意数值、`verified` 或自行编造引用。结构符合不代表事实受支持；候选必须经过真实源审，未送审、条件不足和不确定结果均保留。

数量关系要求同一单位、范围与上限；只有请求数超过经审核上限，才能作受限否定。纯 AND 需求可由一项超限否定整体，OR 或多个独立问题不适用。低于上限也不能推出所有需求都可满足。

计费关系只表达已核实的计量维度及尚未确定的费用输入。CPU 计价列与每次调用运行时限制分开；请求数不能代替 CPU 总量。若已给出充分总量、该费用项或同周期同范围的可靠包内上界，不应继续要求精确 CPU 值。本轮不计算完整账单，也不补造公开资料中不存在的报价。

## 一个内容版本，三处消费

结论集合绑定运行、快照、消费记录、问题／任务、来源和实际生成／源审派送，内容摘要与数据库保存记录的递增版本分开。恢复时从真实生产输入和审核链重建授权，不直接信任保存的 JSON、哈希或 `verified` 标签。

正文、问答和最终 QA 必须引用同一内容版本。源验证、回答交付与最终审核分别记录：有依据的缺项答复或必要澄清可以正常交付，但不表示金额或产品事实已经确定；最终 QA 仍可指出漏答、条件错误和无证主张。未知或混合范围的历史 finding 不批量清除。

## 验收口径

离线部分使用自包含资料，验证候选严格解析、有限推导、价格／澄清覆盖、保存恢复、冷重放与版本篡改。另用既有真实快照作明确标记的离线 mock 接线测试，mock 只替换外部模型响应，不替换业务推导。

真实部分按相同四家固定页面分别回放七个生产阶段，保留既有 8 原题／22 必要分支。每家配置 64 次调用／240000 token／0.25 美元上限，温度 0、重试 0、最多两家并行；实际模型费用以供应商账单为准。

正式正文由独立内容审查核对，分别报告文本、文本加证据、全主张原子和严格系统 QA。空结论集、流程完成、版本一致或模型自报 supported 都不能替代内容验收。旧轮失败与原样报告保持不变。

## 首次审查发现

首候选的针对性回归 417 项通过，变更范围 Ruff 无新增问题；独立规格审查另外运行 152 项测试后仍拒绝批准，原因如下。测试通过不能替代这些未覆盖的反例。

- CPU 输入解析只命中了局部数值，把“0 或 4000 万毫秒”、“0 或 10 美元”和其他周期的数值误作本期充分输入。完整模拟派送链确认它会错误删除 CPU 缺项，而不仅是纯函数标签不准。
- 正文核对另写了一份观察行投影，纳入了已审但未发表的旧推论；当这些推论与正确的结构化数量结论共存时，反而误阻后者。修正必须共用真实发表投影，继续保留对正文篡改的拒绝能力。

上述两项经修复后通过第二候选规格复审。首候选源码、拒绝报告与失败探针全部保留；未据该候选启动全量或真实模型验收。

第二候选规格复审通过，质量审查仍拒绝批准。独立 303 项回归、27 项存储恢复和 2 项 CAS／fence 控制通过，另有 8 组旧路径正文与基线逐字节相同；新增实链反例却发现：冻结再次解析已拒绝的坏提案，零模型派送澄清缺少及时的真实使用验证，以及旧传输边界把重复键／多根 JSON 作为全范围异常。后者是既有行为在新合同暴露的缺口，不宣称本轮引入。

这些问题按局部失败、补交、零派送、持久化及篡改路径修复补测；原始 raw、实际调用及用量保持，旧无 selector 合同不放宽。第三候选增量规格审查另复现了约 2KB 深层 JSON 的 `RecursionError`，完整顶层对象及截断响应均可拖累已审核同伴。最终版将原本无法解析的深度错误规范化为 `ValueError`，保留原文与异常原因；GEN 诊断、REVIEW 和 ANSWER 的后续处理也遵守同一失败身份，不能把失败响应再次交给旧凭据解析器。

## 下一步优先级

1. 将**问题交付状态与事实状态分开**。必要澄清和有依据的缺项可以完整交付，事实仍未知；最终 QA 不能只因没有精确金额或尚未确认保留行为，就把合法交付判成漏答。保留独立反对能力，并按具体子问／缺项与当前版本审核，不自动清除 keep。
2. 将**权限与资源范围推论**纳入有限关系，并统一父题／子任务结论。Cloudflare 跨域 No、1Password 两 vault 及 Trello 并列操作仍依赖自由写作和旧聚合；“已采规则”不等于“已发表回答”，整体肯定不能与未答子项并存。
3. 对**确实缺失的报价原文**补采和重新认证。1Password 的固定定价捕获不完整，缺报价性质及官方下一步；不能靠放宽门禁或借孤立 FAQ 填补。随后加入未曝光样本验收，继续暂不训练模型。

## 验收边界

固定网页捕获于 2026-10-21，不证明当前网页实时性；8 题已曝光，不能作为盲测。四家分别回放不等于一次四产品横向矩阵、自动发现、新网页抓取、完整 Graph、生产语义 RAG 或数据库端到端验收。其他关系仍使用已有任务生成及审核路径，本轮不承诺全部权限和邀请语义均已结构化。
