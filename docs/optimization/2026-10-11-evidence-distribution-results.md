## 1. 证据分配

- 按产品、维度分配完整观察。观察的值、原文、支持状态、条件、证据条目一起保留；冲突双方保持完整，不截断引文以凑容量。
- 未代表的产品优先，再处理未代表的维度。首个来源装不下时先尝试同分支替代；能装下但来源头过大的观察，按真实完整 JSON 成本选择较小的合法观察。
- 同来源的重复原文在视图内保存一次，使用 `quote_ref` 引用；相同原文字串的值也引用该原文。引用只能在当前视图内解析，不借用另一次检索。
- 模型提示去掉重复服务端身份和无效空字段，服务端快照、事实 ID、规范文档/分块、生产凭据、完整 AnswerBoundary 继续保留。非空 Qdrant/知识库分块引用仍进入提示。
- Writer 按实际控制契约计算容量。价格事实被省略时，重新利用释放的控制字段空间；保存已验证可容纳更多产品、维度的候选视图，仍拒绝超出原上限的契约。
- 关闭 first-draft grounding 的全来源旁路。独立 grounding 只包含静态指令，来源、原文和证据数据只来自实际选择的视图。
- `context_budget_exceeded` 表示已采资料被省略。未选中该分支任何事实时，Writer 回答契约明确提供 `evidence_status=collected_but_omitted`，禁止把它写成没有采集。

## 2. 保守能力对齐

针对文档协作，增加共同编辑、评论、提及、权限、搜索、组织、自动化 7 类注解。模型读取原文绑定的能力注解；服务端归并为事实 ID、来源 ID 绑定的覆盖行，用于比较检查。页面序号与原文哈希继续承担观察身份，不能充当跨产品能力身份。

限制与保护：

- 仅内容事实 `evidence_terms` 可以建立能力支持；`slot`、`support_level` 不得补回被完整上下文否定的能力。
- 原文及完整条件包含 Enterprise/付费席位等限制时标记待条件复核；不可用、未启用等否定描述不建立正向支持。
- 共享引用涉及其他产品时保守拒绝归属。封存整个计划的产品目录，即使另一个产品尚未采到来源，也不会丢失其名称。
- 未映射的页面观察保留“需要能力解释”限制，不再制造按 `capability_1`/hash 对不上而产生的假对应方缺口；未知、条件未对齐及部分覆盖仍禁止赢家。
- 目录参与快照内容哈希与视图依赖哈希。旧空目录快照仍能校验；升级产生新版本，旧记录保持不变，相同新输入再次封存复用新版本。

完整链路回归覆盖：语义提取 → 原文准入 → 规范字段 → 封存快照 → 实际视图 → 能力对齐。**这些标签仍是有限规则，不是完整产品能力本体或通用语义判定器**；当前资料不足以证明三产品同轴优势。

### 草稿仍不能交付的原因

三产品覆盖和生成链路已经改善，语义质量仍需审核。例如，把 Confluence 的免费计划宣传概括为适合预算敏感、开箱即用的团队，目前证据不足；Notion 价格省略状态附近引用了功能来源，该引用不能证明价格内容。事实级置信度与来源级置信度也不能混作质量评分。

当前 QA 能检测来源身份及部分结构/覆盖问题，尚不能充分识别这些建议和引用语义问题。不得把本轮 `citations_valid=true` 解读为逐条主张有充分支持。
