# 离线检索与 Agent 证据对齐复测

## 本轮结论

已修复限定范围内的查询与型号保护问题，并补齐离线证据链回归。复杂自然语言的纯稀疏检索仍不足：新候选中，结构化 sparse 的全证据题数只有 2/12，不能据此认定 RAG 已合格。

本轮只使用本机保存资料与已下载权重；外部模型调用、联网采集、在线复核及权重下载均为 0。四产品真实联网报告、生成式事实准确率和部署基础设施未在本轮验收。

## 实际改动

1. **无产品名的主题候选**：明确领域问题可进入 `topic_scope_lookup`，保留原句、未知条件和缺产品诊断，不从语料反推用户要查询的产品。原 005 现能召回对应主题资料，不能把命中理解成用户命题已被支持。
2. **输出要求与事实区分**：独立句尾“请保留原始口径和条件”等不再新增 retention 主题；真实“消息保留”“保留历史”继续用于检索。含主题的其他输出句仍有边界，见下文。
3. **多产品与型号保护**：不同产品、同品牌不同型号的比较或分句保持保守；紧邻名称的数字型号完整保留，包括小数、下划线和数字连字符。独立的时长数字不算新产品；中文引导句之后的型号也跨事实子查询保留，防止 7 与 70 混查。
4. **实际接线**：策略为 `intent-v7` / `lexical-v4`，进入真实 `RetrievalService` 和 Collector，版本参与缓存身份。没有修改 SQLite 索引分词格式。
5. **评测工具**：支持显式候选模式、数据集前缀和产品范围；正式模式拒绝未人审样本。六臂共享参数与模型，执行前后验证输入和实际导入代码的哈希。一次中间运行因改码触发保护而中止，未纳入有效结果；最终锁版重新执行。

- 11 份官方连续短节选，16 道候选：12 回答、2 资料不足、2 需澄清；覆盖 Confluence、Coda、Nuclino，中文/英文/混合查询，含 3 道多来源问题。
- 全部 `candidate`，人审 0；[人审候选审核单](2026-10-15-rag-holdout-review.md) 尚需审核。来源原始全文 SHA、存储哈希与 32 处节选坐标已只读核对，原文没有被作者摘要替代。
- 快照采于 2026-10-10 至 10-13，固定 `as_of=2026-10-13`；原页面发布时间/更新时间未提供。本轮没有检查今天的网页，不能把采集时间当成官方更新时间或当前有效保证。

## 最终本机模型结果

表中计数表示 top-3 片段包含候选判据要求的**全部引文区间**；既不表示答案正确率，也不同于仅命中一个相关来源。

| 查询路径 | 旧已人审 6 答案题 | 新候选：全库 | 新候选：指定产品 |
| --- | --- | --- | --- |
| 原句 + sparse | 0/6 | 0/12 | 0/12 |
| 结构化 + sparse | 5/6 | 2/12 | 2/12 |
| 原句 + hybrid | 6/6 | 9/12 | 11/12 |
| 结构化 + hybrid | 6/6 | 8/12 | 11/12 |

模型为冻结本机 E5-small 和 BGE cross-encoder；`raw` 保留原句，`structured` 使用生产查询规划，两者共用对应版本的词法策略。修改前基线使用 `db7a56a` 导出的代码，输入、产品范围和模型相同；初测与最终结果分开保存。

### 需要正视的差异

- 旧结构化 sparse 总数从历史 5/6，经中间数字误判退至 3/6，最终恢复为 5/6。005 已通过，002 的“用一个工具编辑另一个产品”依赖关系仍保守退原句；不能称原 6 题全部解决。
- 新结构化 sparse 全库基线为 2/12，最终为 2/12；指定产品基线为 4/12，最终为 2/12。安全回退影响了召回，未获得普遍提升。
- 全库中，原句 hybrid+BGE 的全部引文题数为 11/12，结构化版本为 10/12。结构化规划不总优于原句，需要比较保留原句的双路召回与融合，不能只替换原句。
- 指定产品的 hybrid+BGE 取全 12/12 题的金标来源，但只有 11/12 题取全引文。006 所需的角色/工作区前提区间 529–798 未进入最终片段，选中片段从 800 开始；命中文档不能保证上下文完整。
- 全库仅 11 份来源，指定产品时更少；每子查询/每模态取 20 条形成联合候选池，最后取 top-3。候选覆盖容易饱和，不能证明大库性能或稳定精排收益；本轮并发回归也使延迟不适合性能承诺。
- 4 道澄清/资料不足控制题只作检索诊断，没有运行生成式判定。RAGAS 未执行，`semantic_quality_verified=false`。

## 各 Agent 的验证范围

| 阶段 | 实际执行与检查 |
| --- | --- |
| Planner / Survey | 明确计划范围；real Survey 缺外部研究时明确跳过，不造事实 |
| Collector | 真实 RAG 工具与 SQLite；按产品检索，过滤错项目、历史报告、过期及未标产品资料；命中仍需提取和准入 |
| Analyst | 产品×维度视图，冻结事实/来源；可变 live 对象更改不进入输入 |
| Comparator / Reflector | 消费同一快照及有效上游产物，检查依赖；相关来源更正后旧产物失效 |
| Writer | 真实分维度写作逻辑、引用绑定、hardening、发布结构校验；跨产品引用被剔除，即使固定审核回复声称“支持” |
| QA | 真实最终审核与证据消费记录；报告和所用快照保持可追溯 |

新贯通用例使用双产品合成夹具、固定捕获字节与 LLM 回复，socket 联网被禁止；**没有替换报告 hardening**。旧贯通用例仍有 hardening 替换，两者验证范围分别说明。这证明执行/保护规则，不能证明真实大模型在新问题上的报告语义准确率。Collector 负责检索，后续五类 Agent 通过同一准入快照获取匹配信息，不各自自由取新资料替换引用。

## 已知限制与下一步

1. **先审核新候选**，确认角色、套餐、访问前提和缺证判据；批准前保持诊断用途。再另留真正未被调优者接触的候选批次。
2. **查询保真与双路融合**：比较“原句 + 结构化查询”，保留工具依赖及未知条件。旧 002 与“请保留电池和续航的原始口径”一类输出句仍未完整解析，后者可能多召回 retention 候选。
3. **证据上下文补全**：在相同 canonical 版本、范围及预算内展开父块/相邻块；把角色/工作区前提纳入逐条主张核对，单独评测多引文完整率。
4. **随后验收真实生成**：用独立人审的答案/报告主张与引用检查验证语义。四产品联网流程及 HTTP Qdrant、Temporal、Redis、Postgres 部署验收仍需另行执行。
