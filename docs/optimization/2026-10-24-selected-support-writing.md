## 1. 本轮改动

### Writer：先选完整支持，再限定写作

- 新增 `task_support_selection.py`。每次任务生成前，在本批实际派送的规范目录中进行一次有界、仅返回引用的选择；操作／谁可操作使用 o-reference，其余规则使用完整 s-reference。最多一个操作或必要例外对的两个片段，不切条件。
- 选证是未核实提案。非法、外国、重复、遗漏或无完整支持的项显式延期／缺证；成功同行保留，不提供默认引用。
- 生成载荷逐任务列出所选引用和完整可读支持，输出引用集合必须与该任务所选一致；随后继续原绑定解析、主张守卫和独立审核。父事实、兄弟片段或诊断不能补足窄引用。
- 选证及生成均验证本次唯一匹配的真实 agent／scope、完整 system 和 user、输出及 transport。生成回执不符则整批延期，不解析主张、不进入审核；操作可读身份从规范原始事实恢复，非法追加行无法覆盖。
- 初稿和原有局部修复均经过选证；新增调用纳入原24次／80000 token上限。选择完整引用没有解决一般自然语言的单谓词写作，也不能保证场景结论正确。

### 最终 QA：明确身份，继续有界审核

- 使用 `independent_questions_v2`。显式发送整题 `expected_claim_ids`，局部任务支持另列 `task_support_claim_ids`；返回仍须严格回显整题 IDs，包括空列表，不能以任务 ID 替代或授予整题资格。
- 每次最多六批，每批最多10项、6000 UTF-8 bytes；完整题目超窗则整项未送。未送项优先于已付费失败项，同类先审原题，再审历史问题。合法同行缓存，每项同一依据仍最多两次实际请求。
- 新运行最终 QA 预留覆盖实际完整请求上界：system＋6000B user＋256余量＋1600输出，当前11000；最终回答12000、全局24次／80000 token不变，旧明确预留保持。调用预留按问题数有界安排，不超全局。
- 有可继续派送的待审项时保留阶段；新依据重审只重新打开阶段，旧调用和扣账保持。全部完成或已无可继续项才释放。超时、失效、预算拒绝与未送继续分别记录，`completed` 不等于报告通过。

## 3. 剩余缺口与下一步

1. **单谓词仍未落实。** 1Password 两条已发表主张均重复包含“无 Private vault”和“单共享库”；Cloudflare 两条同义稿均把收费与运行限制合在一起。完整受引用支持不等于原子。下一步应将任务目标谓词与所需前提分开，拒绝附加兄弟结论，并避免局部修复重复发表原有内容。
2. **Trello 尾部是预算准入失败。** B 投票、跨板、改权角色及计费任务未生成，不能说官方资料没有这些内容。三次选证拒绝时已用46055、保护回答与QA共23000、另留3200余量，输入预留分别12113／10490／11006，另需600输出；触及的是 token 保护。应先减少重复实际载荷并按剩余任务安排写作／最终审核，保持完整前提和全局上限。
3. **Bitwarden 容量回归。** 两次生成均是复合规则，没有交付题设3人、3 collections 的明确否定。审核中完整 operation 条件实际包含额外容量规则，不能把它误写成“资料没进窗口”；稿件复合、任务未完成和审核判断须分别修复。
4. **Cloudflare 权限绑定仍缺口。** 初稿选择 span 却生成操作推断，被 `operation_binding_required` 拒绝；修复选择缺证，权限答案未发表。应明确任务所需绑定种类与实际可选操作的对应，不能放宽引用守卫来发表。
5. **1Password 报价仍部分回答。** 安全拒绝精确人民币含税总价有效，但不能代替公开报价性质和有证据的官方下一步；首题最终QA还需在不裁条件的前提下压缩重复上下文。
6. **QA 合法回显不等于语义正确。** 模型仍会借 `unverified`／`support_verified=false` 否定已经可见的有证局部回答，也会把安全拒绝完整金额当作未答。应核对实际正文与任务解释，继续区分整题资格、局部交付和合理拒答，不能靠修改状态标签或放宽身份检查消除阻断。

本轮没有证明报告合格，也不支持开始训练或加入更多基础设施。下一轮优先处理任务谓词、真实载荷和合法绑定的交叉问题，再以同一正式口径复验。
