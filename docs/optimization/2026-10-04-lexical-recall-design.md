# 离线关键词召回改进设计

日期：2026-10-04。基线：`7527bd2`。用户已授权执行上一阶段交付中的下一步：改善召回并准备代表样本审核。沿用离线评测范围；人工审核、真实语义模型和 Ragas 的状态保持真实记录。

## 问题与取舍

实际回放中，“请问保修有效期多久”生成八个必需二字词，即使正文有“保修有效期”也返回空。FTS5 对相邻查询项使用隐式 AND，依据 [SQLite 官方文档](https://sqlite.org/fts5.html#fts5_boolean_operators)。原 tokenizer 不做中英文对应；之前 5 个候选答案题关键词指标为 0，不能作为语义模型结论。

采用严格匹配加受控补召回。全词 OR 容易让产品名称或一个普通词召回无关段落；模型翻译会增加本轮之外的依赖与调用。受控方案保留原问题与原索引，通过固定问句停用词和版本化双语术语构造第二条查询，并保留未知关键词及显式数字约束。不把标准答案、来源正文或引用常数加入查询。

## 召回合同

- 原严格 FTS 查询继续保留，正文匹配优先。严格正文不足 `limit` 时才执行补召回；两条 SQL 使用相同的可信 scope、产品、维度、市场、角色、时效过滤，过滤均在 LIMIT 前。
- 术语表只含通用概念：battery、capacity、warranty、duration、refund、shipping、export、license、subscription、billing、monthly、annual、pricing、plans、guest、seat、update、security、history、retention、deletion、handoff、privacy。没有品牌、价格、年限、来源 ID 或查询 ID。
- 同概念的中英文别名用 OR；不同概念和保留下来的未知词 / 数字用 AND。匹配别名时先长词、英文完整词边界，避免 `annual` 匹配 `biannual`、`seat` 匹配 `seattle`。
- 只从查询中移除明确给定产品范围的完整产品名片段，不按词集合删除型号数字；查询中另行出现的数字仍保留。没有产品范围时不猜测品牌，未知关键词继续限制正文召回。
- 最多 8 个概念、12 个未知词项；超过边界关闭补召回并报告原因，不能默默截掉限制条件。问句停用词只处理固定语气 / 问法，例如“请问”“是什么”“多少”“多久”“的”及英文 what/how/the/can 等；未识别的内容不得随意删除。
- 补召回只搜索正文；严格标题匹配仍保留，但排名低于正文，不能借产品标题把首段当支持事实。相同状态下严格正文优先于补召回正文；已有 stale 折权保留。
- 记录版本与命中路径（strict_body / fallback_body / title）。诊断标记不进入来源授权或事实置信度；正文、hash、版本与源 metadata 不写回。RetrievalService 仍回查 canonical 文档和块，只保留仓库生成的这项检索诊断。
- 支持显式 `lexical_fallback=False` 的仓库用于严格基线 / 回滚；默认启用。现有 tokenizer、索引、Qdrant、快照、分块及 rewrite API 不变。

## 数据隔离与评估

另建 `product-research-tuning-{corpus,queries,labels}.jsonl`，使用虚构产品和合成资料，全部 `purpose=tuning`、候选标签，无人审身份。包含中英双向术语、自然问句、未知主题、数字限制、同产品不同主题以及错误市场 / 型号 / 角色 / 日期。它只能验证合同，不能证明真实产品或跨语言语义质量。

benchmark 增加显式 `tuning-diagnostic`；原 formal 仍仅接受人审 evaluation，候选正式问题仍使用 `candidate-diagnostic`。各模式选取各自 purpose，记录选中与排除数量。提供 `--lexical-policy strict|bounded`，同一份原查询、资料和标签分别运行，记录政策版本、原文引用覆盖和非 gold 来源数量；答案题主指标继续按 doc 去重。

先固定术语和调参合同并验证，再运行原候选 evaluation 资料一次比较；不根据其分数改词典、标准答案或查询。完整问题未获人审，结果始终只作诊断。不同缓存 / 日期 / 文档归档规则沿用上一阶段合同。

先观察失败回放，再做最小实现。实际临时 SQLite 测试覆盖问句、双语、数字与未知词、词边界、溢出关闭、正文优先、标题非证据，以及每条 SQL 的权限 / 产品 / 市场 / 角色 / 日期限制。已有版本、缓存、结构、scope 与 benchmark 回归继续执行。

保存合成调参对照和原候选对照；增加代表样本审核单，列原问题、事实范围、引用、市场与日期、待确认完整性。执行授权不视为人审标签，未获事实审核的仍 candidate。最后完成完整后端回归、审查、增量 lint、密钥模式扫描与 GitHub 交付。

该策略不做全文翻译、向量检索、复杂实体别名推断或事实回答；未知术语可能仍召回失败。过往短节选与动态报价覆盖不足的问题仍存在。
