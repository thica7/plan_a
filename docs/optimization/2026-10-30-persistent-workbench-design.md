# 本机持久化任务工作台设计

状态：用户于 2026-10-30 批准执行上一轮建议的 P0。基线为 `b744fa0e1db4857df99668ae333687eb2e636a55`。本轮只做可长期使用的本机演示闭环；Docker、Kafka、报告版本并发事务、模型训练和报告语义修复不在本轮实施范围。

## 选择与边界

采用原生 PostgreSQL + 现有 SQLite 执行存储。PostgreSQL 同时承载企业项目／报告元数据和提交中心，避免业务元数据继续使用 Memory。知识库／运行日志／检查点仍按现有职责存储，不宣称全部迁到 PostgreSQL。

仅持久化提交中心而保留 Memory 企业存储虽然更省改动，但重启会丢失项目元数据；全部退回 SQLite 不满足用户本轮数据库目标。因此选择完整企业 PostgreSQL schema，并满足其 pgvector 依赖。pgvector 按官方源码针对本机 PG15 安装；应用启动器只检查依赖，不自动下载安装软件或修改任意数据库。

工作区使用独立的 `runs/local-workspace/`，不覆盖原 `runs/run_journal.db`、知识库或旧报告，也不自动导入旧演示。新数据的持久化和恢复通过真实重启验收。用户可以显式选择启动新工作区；全局任务中心开关默认值仍为 false，根 `.env` 不改、不复制、不显示。

## 数据与进程

- 工作区内 PostgreSQL data 目录有独立归属标记，0700；socket 在系统临时目录的固定短路径，以工作区规范路径哈希区分，避免 macOS Unix socket 路径超长。
- PG 仅私有 Unix socket，不开放 TCP；本机相同系统用户是受信任边界。应用连接使用非 owner、NOSUPERUSER／NOBYPASSRLS／NOINHERIT 角色；管理角色仅初始化 CLI 使用。该方案不代替内网部署的密码与 API 鉴权。
- 初始化先创建企业 schema／默认工作区，再应用提交中心原有三份迁移并授最小权限。已有迁移 SQL 不修改。停止保留全部数据，无 destroy／自动清库操作。
- API、Relay 共用工作区内的 run journal 和图检查点；新增可配置图检查点路径，默认仍沿用旧值。产物、知识库缓存也隔离到工作区内。
- 独立启动入口管理 PostgreSQL、API、Relay 和 Vite；默认 API 8010、前端 5180，均绑定 loopback，端口占用时拒绝启动，不结束占用者。
- 启动环境显式隔离根 `.env`、模型凭据、Redis、Qdrant HTTP 和 Temporal，demo 图不发外部模型请求。Vite 同样遵守关闭 env-file 读取的标志。
- 持久化进程记录只保存归属与非秘密状态；停止核 PID、创建时间和实际命令，无法确认时拒绝发信号。只停止本启动器创建的进程，启动失败清理本次进程但保留数据库文件。

## 用户流程

桌面新增“提交中心”入口，保留现有任务历史。`/submissions` 展示当前工作区的提交列表、状态筛选、游标翻页和本月额度流水；`/submissions/:id` 展示单条派发状态、运行状态、错误码与关联报告入口。

新建研究读取 `/api/runtime` 的 `task_center_enabled`。开启时调用新提交接口并进入提交详情；关闭时维持原 createRun 路径。一次表单提交在网络失败后的重试复用原幂等键；修改业务内容生成新键。不能因新接口错误而偷偷回退到旧创建接口。

取消只对合法 pending 单开放，服务器仍做最终判断；失败派发显示“重试派发”，不把它描述成重写报告。`dispatched` 与 `run_status` 分开展示，报告语义合格不由任一运行状态推断。页面默认中文，沿用明亮像素风和现有可访问性／交互审计约定。

## 验收

1. 初始化与停止不会删除／覆盖既有目录；归属不明、PID 复用、端口冲突均拒绝；preview 不创建目录／进程／连接。
2. 真实 PG + pgvector 完整企业 schema，在受限 app 角色下写入、查询、投影报告与提交账本；应用环境没有管理角色连接。
3. 从真实 API 提交 demo → Relay → LangGraph → 运行完成 → 前端打开结果；数据库行、run ID、检查点一一对应。
4. API／Relay 重启及 PG 停启后，同一提交、一次预占、项目和报告版本仍存在；不是依赖进程 Memory 恢复。
5. 同键重试、并发提交、合法取消、派发重试、额度耗尽、API 断开、Relay 暂停都有可辨识 UI 状态；不误报成功。
6. 全量后端回归、相关前端交互测试、标准 OpenAPI／TS 生成、构建、实际配置 Ruff 新增 0、凭据扫描；保留首失败与原始证据。
