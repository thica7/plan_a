# DeepSeek Search／Fetch 与证据消费交付

日期：2026-10-19。工程验证与四组首次真实复验完成；**系统交付仍为 0/4**。独立审读仅认可 Cloudflare 两道限定问题的内容，不能视为完整产品报告或用户验收。暂不训练模型。[结构化结果](2026-10-19-deepseek-web-delivery-results.json)。

## 1. 新网页接口

独立调用官方 `POST /v1/tools/search` 和 `POST /v1/tools/fetch`，不再为这些工具请求额外调用生成模型。配置 `WEB_SEARCH_PROVIDER=deepseek`、`DEEPSEEK_WEB_API_ENABLED=true` 后启用；开关默认关闭，旧模型工具和浏览器链保留。

Search 返回待核验的来源候选。Fetch 返回标题与 Markdown 原文，使用固定官方端点、实际请求 URL、正文哈希和观察时间记录来源凭据；原站 HTTP 状态、重定向最终 URL 没有由接口提供，保持未知。正文仍须经过内容检查、来源准入、逐条事实验证和 canonical 重放。API 成功不授予主张支持资格。

Fetch 在原有 advanced 次数内补充低质正文或结构缺口，一次失败后保留原结果及原因。登录、验证码、robots 和 SSRF 检查保留。新 provider 路由暂不使用 Redis 抓取缓存，避免把历史调用计数重复计入当前额度；旧路缓存行为不变。同页 RAG 复用仍按既有规范正文、范围和时效规则执行。

工具请求、成功响应及成功非空的计费请求估计分别统计，生成模型调用和 token 另计。新 Fetch 请求若被总超时取消，已开始的请求仍进入 error span，取消原样传播，不补抓或重试；未开始时释放 advanced 预留。已开始但未收到响应的计费状态单列为 unknown，不能以成功请求估计为 0 宣称未收费。费用估计不是账户账单，不因非空内容被本地拒绝而把实际请求抹去。

官方资料：[Search／Fetch 指南](https://api-docs.deepseek.com/guides/search/)、[Fetch 接口](https://api-docs.deepseek.com/api/fetch/)。官方说明 `deepseek-flash` 当前指向 1017 更新；实际日志若只返回该别名，不能据此独立证明服务器修订版本。[更新记录](https://api-docs.deepseek.com/updates/)

## 3. 工程与语义验收

Task1：254 项相关测试通过；SPEC、QUALITY 与根代理分别复跑。已修复维护页附带请求编号、版权尾注仍被误收，以及缓存重播造成 API／advanced 额度重复计算的问题。正常正文及尾注原文哈希、旧路缓存、SQLite／canonical／snapshot 链均有回归。

### 通用章节身份与计费选窗

HTML 抓取在同一正文根中保留真实标题的 DOM 身份，并将位置映射到最终正文；元数据绑定标题、层级、出现顺序、偏移与正文 SHA。临时标记经正文选择比对后清除。已有折叠问答只允许在实际 DOM 出现次数内恢复完整原文块，不能用短答案子串掩盖正文变化。

无法确认标题与未绑定正文的位置关系时保留缺口，不把标题猜补到文尾。HTML 的非空标题必须有完整 DOM 路径；无标题 HTML 不把代码中的 `#` 注释当结构。独立 Fetch 的 Markdown 使用完整标题行和代码围栏校验。旧的无歧义章节可兼容，重复标题仍不能凭首个文本匹配猜位置。

原来的命名服务、完整表头、CPU 单位、全部脚注、最低费用及容量检查保留。当前 Cloudflare HTML 离线重放恢复 30 个标题，计费窗口从空变为 5,730 字符；规则提取与实际模型入口 mock 分别经过原准入、SQLite、快照与 Writer 视图，完整表头、四条脚注及最低费用前提均保留，视图为 5,635/8,192 bytes。这里没有真实模型调用，不等于模型会正确回答账单。

三版修复后，341 项相关测试通过（含审查者的三个独立反例）；SPEC、QUALITY 与根代理各自复跑，独立重放当前 HTML 的两条完整链。审查期间发现并修复了未标记正文造成标题错位、丢失路径误收及无标题代码页误拒；各版冻结记录保留。

### Writer 原句消费与最终回答

增加 Writer 本地的删除、离职、归属、保留意图匹配，优先选择完整生命周期原句及相关例外。独立核心分支共同受总八条／14000 bytes 约束，普通每题三条不再截去第四个必要分支。真容量缺口进入已有 prompt 和 audit gaps；遗漏完整原文、值和条件均相同的冗余 ID 不误报不足，不合并事实或来源身份。

中文“没有／只能”和带明确账户范围的 SSO 结论保留实际主张、片段、角色对象、否定、数量与必要条件核对；仍拒绝示例、引述、疑问和不完整条件。已给购买产品、期限、币种、税费和实际付费席位仅作请求条件，员工不换算席位，一年不推断年付；答复不重复索取已给条件。缺报价审计完整当前快照，一般不完整输入保留 partial，具体合格不足答复按原合同验证。

审查中发现并修复每题三条截去独立核心、已给席位重复询问、冗余 ID 引发假缺口等问题。第一次全量回归为 43 失败／5928 通过／1 跳过：42 项来自新增裸“访问”误认非断言，一项为已知套餐文案冲突；旧日志保留，未放松旧测试。随后独立审查又确认旧停止规则仍丢弃第四条不同条件；删除两行规则并补双预算真实 Writer 链反例后，最终 564 项相关测试通过，SPEC 和 QUALITY 各自独立复跑通过。预算充足时完整例外进入最终答复，超容量时继续阻断。

## 5. 剩余问题与下一步

1. **Collector 的正文结构与条件窗口。** 1Password 两页新 Fetch 均返回 API 200，访客页 2309 字、定价页 2541 字，仍零准入事实。访客页七条提案均因 `condition_capacity` 拒绝；新 Markdown 还携带旧 basic HTML 的结构缺口。应分别记录每次捕获的结构与缺口，恢复可绑定的段落／条件窗口，验证超容量的具体原因；不能直接清空缺口或抬高上限。定价正文仍缺完整报价 FAQ，不能拿继承的空 disclosure 补成事实。
2. **按题分配证据及按实际主张闭合例外。** Bitwarden 已有 Free 限制原句仍未回答第一题；第二题没有完成移除成员／删除账户和个人／组织条目的澄清，还把知道主密码概括为可继续登录，遗漏特殊账户恢复和移除前登录条件。下一步核对逐题预算与必要证据选择，并对实际生成的登录等副结论重新绑定完整例外；不能只按问题关键词决定是否保留例外。
3. **门禁按问题与报告模式适用。** Cloudflare 的两题内容、引用与不足答复正确，仍被价格及完整比较范围规则阻断。应逐项修复有实证的误阻，并保留 Bitwarden 这类条件错误的拦截；不把所有 blocker 一律降级或放行。
4. **Dropbox 的来源获取。** 本地仅得导航壳，新接口两页仍返回工具服务 404。需要验证当前官方替代入口与有界抓取策略；不能推断源站文章已删除，也不能借旧正文冒充本次抓取。

新网页路线默认关闭，本机 `.env` 未改；本轮只在隔离 CLI 临时启用。当前结果不足以推广为已合格的生产路线。继续优先处理证据窗口、逐题交付和门禁适用性；Agentic RL、模型训练和新增基础设施本轮均未执行，`reward=null`、`training_ready=false`。
