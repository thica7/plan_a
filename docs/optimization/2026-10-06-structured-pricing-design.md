# 结构化报价证据链设计

日期：2026-10-06。基线：`13612d1`。用户已授权实施上一轮建议的下一阶段。

## 目标与范围

打通离线可验证的「采集正文 → 价格抽取 → 准入 → 归一化 → RawSource → 证据快照 → Writer/QA」链路。当前缺口是报价只保存展示文本，同一报价的金额、币种、席位、税费等条件会丢失。保留旧报告和旧文本报价兼容；新字段采用增量契约。

本轮不调用模型、不下载权重、不读真实知识库或账单、不改冻结评测集。002 的渠道报价及时间窗、038 的完整账单仍待补齐，不计算平均价或总费用。

## 数据契约

- `NormalizedPricingField.price` 保留原展示字符串。
- 新增 `qualifiers` 和可选 `market`。金额、币种及报价条件按逐条报价写入 qualifiers，复用现有 answer guard 的字段合并规则。
- 保留逐条报价自己的原文、EvidenceItem ID、来源 URL、竞争产品和置信度。去重包含来源及条件，不能合并不同席位、市场、税费或渠道的同金额报价。
- 归一化只传递已准入字段，不从展示文本重新猜条件；不把字典转为 Python repr。输入不能被原地修改。

## 确定性抽取与准入

首版支持同一正文行内可明确绑定的报价，保留每行原文。金额为有限且非负的数值，零有效；布尔值、负值、歧义数字不升级。币种必须有明确代码或明确币种文字；单独 `$`、`¥`、`元` 不补成 USD/CNY。

年付/月付、套餐、席位、市场、容量、成色、税费和渠道条件只使用同一报价原文的明确表述。双价格或混合条件无法唯一绑定时，保留旧文本证据，并让缺失字段阻止完整回答。不得用研究请求的地区、产品类别或页面元数据填补条件。

结构化字段在准入时与原文重新比对，伪造字段、跨行条件和不存在于正文的摘录不能成为可信报价。所有 `price_rows` 均适用，不信任抽取器名称。现有 SaaS 和通用产品两条抽取路径均适用。

官方当前价资格必须依据真实最终 URL 的官方归属及定价/购买页面语义，不能仅凭候选 origin 或页面自称。历史/发布价、带来源日期的价格、过期缓存不得因重新抓取或重新归一化变为当前价。验证事件与抓取事件分开记录；验证时间不能绕过原始采集时间和来源日期的限制。未知来源、未知市场等保持缺失。

实施后的首版保守策略：任意非空 candidate/typed 来源日期均阻止当前价升级，不把无法解析的日期当作没有日期。单价行含 `not/no/without/unless/excluding/or/或`、标注字段内的并列选项、混合席位/税费，或数值区间时保留 legacy 原文，不生成完整结构条件，并清空旧套餐/周期以防 fallback 补回。显式席位标签与自然语言席位也必须一致。这会降低部分合法条件句及复合名称的结构化覆盖率，后续由真实标注样本评估。

正文级来源标记由实际抓取结果生产端提供，成功正文与搜索摘要区分。失败、摘要和任意页面元数据不能升级为 full_source。同一来源多市场且无法唯一归属时保留未知市场，不拆来源或扩大快照契约。

## 验收

使用固定本地正文替代外部 fetch 边界，其他环节使用真实代码。验证完整设备/订阅报价可被 guard 读取；缺税费/席位/币种/市场、年付月付混杂、跨报价条件、旧日期和伪造元数据必须保持 partial/insufficient 或拒绝准入。Writer 与 QA 消费同一快照与边界。不得为了测试通过放宽 guard。

现有相关基线测试：230 passed。完成后执行新增用例、后端全量测试、变更 lint 检查、冻结文件哈希核对及脱敏密钥扫描。独立规格审查和代码审查通过后写交付文档，提交现有分支并验证远端 SHA。

## 已知限制

动态定价开关、复杂表格、跨行优惠及多币种多地区映射不在首版完整抽取范围；这些场景保留文本或返回缺口。离线测试不等同真实联网采集、真实模型生成或 RAG 合格验收。
