## 本次修改

- Writer 生成使用 GEN5／单主张审核 v3。首次生成和逐条审核后，对当前题缺失、解析失败或审核未通过的任务最多定向补交一次，从同一已授权证据池重新选择完整材料。补交使用新命名空间，保留已通过主张的文字、身份和审核。每题最终仍至多8条；真实调用照常计量，Graph 重做配额不增加。
- 上限推论只接受同主体、套餐、对象、操作和计数人口的有限关系。首轮 v3 新增同一完整事实内“即／i.e.／that is”的组织用户共享人数重述；完整前置及括注条件不能被删去。
- 新 QA9 明确服务器当前 canonical 子问与历史 finding 的不同范围。父题提供共享题设，不附加兄弟输出任务，也不成为产品事实。历史 finding 仍完整审核。父题在 receipt 中按真实绑定的全部子问汇总，分别记录交付完成与事实解决。
- QA9 用户输入完整明文上限为14000 UTF-8 bytes，SYSTEM 为3844 bytes，fresh 请求保护19702。QA5–8 的原始 SYSTEM、窗口和回放身份保留。六批为每个执行窗口上限，恢复可续窗；每个 finding 累计最多两次实际尝试，仍受全局预算约束。已有 checkpoint 的额度和费用不重置。超窗保持未送审，不裁剪条件；模型 keep 不被服务器改写。
- 公共 API 合同按现有流程同步 OpenAPI 和 TypeScript 类型，没有界面改造；实验开关默认仍为0。

## 第三检查点的实现边界

v5在ANSWER解析、canonical绑定、正文投影、认证重放和最终QA资格中显式传递真实facts。新来源路径仅支持完整无条件组织共享资料的collections上限：重新核对已发表fact的精确source span、成员、hash、位置与身份，再求已发表属性和原文的交集。缺facts、未发表属性、错误产品、不同套餐、条件、例外、日期、分组和排除口径均不能补出No。正确品牌一侧省略可通过已验证产品身份对齐；显式错误品牌仍拒绝。旧v1–v4的SYSTEM、语义身份和原失败回放保留。

这是有限来源证明，尚未解决任意自然语言的数量推论。GEN5、REVIEW3、QA9、全局预算和默认实验开关保持。公共ANSWER envelope仍为v3，子问前提合同版本为5，两者不是同一版本号。

### 修复效果与剩余阻断

1. **已修复的投影路径：** 用第二轮同一真实输入、主张、ANSWER和接受快照重放，旧v4为unknown，v5带真实facts可保留No；缺facts继续拒绝。正确品牌单侧省略、英文前导问句和未消费嵌套scope的三项审查反例均完成红绿闭环。这个反事实诊断不计第三轮真实正文成功。
2. **第三轮BW仍失败的原因：** 生成器把人数能力与上限、核心功能与collections共享写成复合主张；一项在任务约束中拒绝，另一项独立审核拒绝。有限补交重复了失败写法。虽然collections场景推断已获支持，最终没有独立合格cap事实供ANSWER作数量见证，实际模型提出No仍降级。不能把它描述为缺网页或已彻底解决BW交付。
3. **任务审核与发表仍不对齐：** Trello跨板推断、BW上限推断和Cloudflare请求部分算术已支持却未进入最终回答；1Password也有明确上限规则却缺直接场景否定。需要修已审核任务结论的证据类型与前提合同，使事实与推论各自保留身份、完整条件和引用，再逐题核正文。
4. **引用审核还有假阳性：** Trello计费结论被模型放行，但绑定的原文只有逐成员逐看板权限。Cloudflare复合推论额外前提亦未选完整支持。后续要按完整主张审核，不从未选后文补证。
5. **QA范围只完成接线与派送：** 实际wire明确current_question只问A/B投票，模型仍以下载、导出、义务未答作keep，这些兄弟题本轮已分别审核通过。服务器没有偷偷清keep，父题保持不完整。另有A否/B是总标签yes、计费子分支unknown但后文发表否定结论，两处规范状态与呈现不一致。重放字节一致不能证明语义一致。
6. **报价与计费仍需有效局部答复：** Cloudflare缺CPU用量要求；1Password报价捕获有空disclosure／不完整标记，后续未提取、未入库。之前部分页面报价仅在metadata时也未进入提取输入。它们不能被当成官网没有报价规则，或只显示“未核实”即可交付。

后续优先修任务原子生成、已审核推论到结论的合同、QA范围与总标签一致性；随后补报价结构和解释性缺项答复。继续沿用独立逐题正文验收，不以增加Agent数量或训练模型代替这些失败修复。
