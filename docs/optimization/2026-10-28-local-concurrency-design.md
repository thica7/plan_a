# 本机并发治理设计

## 授权和目标

用户已批准按任务准入与背压、共享执行状态、全局模型并发、缓存去重和压力测试的顺序实施。沿用当前工作区和分支，Docker 留给另一台部署电脑，暂不增加 Kafka，不调用付费模型做压力测试。

本轮目标是让同一台机器、共享相同运行数据库的两个进程遵守同一容量和执行归属规则。它不是跨机器高可用、Redis/Temporal 容器验收，也不承诺外部调用 exactly-once。

## 方案选择

1. 采用共享 SQLite 协调表和同机内核文件锁。无需启动新服务，可以用真实多进程验证；范围限定为 POSIX 本机及后续 Linux 容器。
2. 仅用 asyncio 队列实现简单，但无法约束另一进程，不满足本轮共享状态目标。
3. 直接依赖 Redis/Postgres/Temporal 服务更适合后续部署，但当前机器没有这些可验收服务。保留已有适配，不将离线测试描述为真实服务通过。

新增协调功能显式启用，默认关闭以保留现有部署兼容性。正式本机验收通过实际启用的 API、服务和模型 transport 入口运行，不能只测试未接线的协调类。启用后配置错误或协调存储不可用须明确失败，不能退回各进程自行计数。

## 协调与背压

协调表放在同一个 RunJournal 文件数据库中；配置路径必须与正式 RunService 的 journal 路径一致。默认全局运行上限 2、工作区运行上限 1、全局等待上限 32、工作区等待上限 8、最长等待 60 秒。模型总并发沿用 LLM_MAX_CONCURRENCY，默认 4，模型排队最长 30 秒。这些是可配置起点，不是测得的容量承诺。

- HTTP 返回接受前，原子预留一个有界 ticket。相同 run/操作的幂等重发不重复占名额；不能先创建无限量后台 task 再等待 semaphore。
- 全局或工作区排队满时返回明确容量错误及 Retry-After；队列过期、请求取消和启动失败须收尾，不永久占名额。
- 领取时同时满足全局、工作区和 run 排他规则；同一工作区内按入队顺序，不能被后来的同区任务插队。可运行的其他工作区不因前一工作区已满而全部停住。
- 人工等待不占执行名额。新建、恢复、人工续跑、手动重做、自动重做和 Temporal 活动执行都必须经过统一准入，嵌套自动重做沿用当前所有权。

## 所有权与持久化

每个 run 的执行者持有 token/generation、心跳信息和内核文件锁。不能仅因心跳超时抢占仍持锁的活进程；进程退出后由操作系统释放锁，后续显式恢复可取得新 generation。部署配置不一致须拒绝共享同一名额池。

- 高层执行 guard 覆盖首次状态修改、图执行和最终提交。resume 的租约显式移交给已成功创建的后台任务，HTTP 返回不释放仍在执行的租约；取消不得重复创建续跑任务。
- 执行写入携带 generation/token，旧执行者在释放或接管后永远不能写回。空闲控制写用 journal revision CAS，不能以“目前没有 owner”为由允许旧快照覆盖。
- 命令审计使用只追加控制事件的方法，不在后台任务已接管后重新保存 HTTP 线程的旧 detail。
- 事件 ID 在数据库事务内分配，生产新路径不使用 len(events)+1 或 INSERT OR REPLACE 覆盖事件。
- GET/list/hydrate 不替其他进程执行状态修复。持久 SSE 按数据库游标增量补读，能接收另一进程提交的事件；内存兼容路径使用有界订阅缓冲。
- 内核 run 锁覆盖图检查点写入，不在 await 图/网络期间持有 SQLite 写事务。取消需要等待本次执行退出后再释放锁。暂停进程不自动被超时夺权；这是本机安全边界。
- 新异步协调 I/O 使用 await to_thread 和短事务。现有同步持久化调用保持同步有序和有界，不将其丢入未 await 的后台保存；未完成整条存储链异步化需在交付中保留说明。

## 全局模型名额

在真实模型 transport 尝试前取得同机共享 slot，覆盖普通生成、重试、备用 provider、RAG 查询改写及原生模型搜索。保留原 per-run 预算、真实请求计数和限额。

排队超时或在发送前取消不能记作实际 transport；退避等待不占名额。名额由固定内核 slot 锁保护，进程退出可释放；不得按 TTL 抢占仍持锁的进程。仅约束本机客户端在途请求，不保证取消后远端服务立即停止计算。

独立 Search/Fetch 工具 API 与生成模型调用分开，不把工具计费伪装为模型 token。本轮不宣称实现服务商 RPM/TPM 的完整分布式调度。

## 缓存并发去重

先实现有界单进程 single-flight：相同公共网页及相同 Query embedding 的并发请求共享一次实际计算。不同选项、模型版本、检索范围不能错误合并。每个调用者取得独立结果副本，取消一个等待者不影响其他等待者；无等待者时取消无用工作，异常后清理键，容量满明确拒绝。

公共网页保留原采集时间、哈希和来源准入。价格、登录/凭据/查询串 URL、强制刷新及独立 DeepSeek Fetch 的现有绕过规则不放宽。检索结果复用仍重验 canonical 证据，不缓存或复用未经认证的 QA verdict。

Redis 路径补可选带 owner-token 的缓存互斥和释放合同，使用共享假客户端验证跨实例竞争；真实 Redis Lua、TTL、故障及跨容器结果留部署机器验收。Redis 未启用时仍验证本进程去重，不能将它宣传为跨进程共享缓存。

## 验收

1. 真实临时 SQLite 与独立进程验证准入上限、按区公平、幂等、超时、取消、进程退出后的回收和旧 token/revision 拒写。
2. 使用实际 API/runtime/RunService 入口验证 queue-full HTTP、run_pipeline、resume handoff、scoped redo、自动重做与 Temporal 活动的 busy 语义。
3. 在真实模型名额保护内部使用受控 transport，混合两个进程、普通生成和查询改写；全局峰值不超过配置，重试/异常/取消后名额归还，未发请求不虚记 transport。
4. 两个服务共享 journal 验证 GET/list/SSE 状态与事件游标；读取方不覆盖活跃执行者。
5. 同页/同 embedding 并发去重，选项和作用域隔离、异常、取消和冷缓存突发；Redis 仅合同验证单列。
6. 有界压力脚本使用隔离临时目录和合成执行，不读本机 .env、不调用外部模型、不连接现用数据库。记录 admitted/rejected/expired、运行与模型峰值、完成/等待延迟、错误及资源清理；性能数据只对应本机合成场景。
7. 完成独立规格/质量审查、相关与完整后端回归、必要接口生成和最终凭据扫描，更新 README/Agent 说明/交付记录。沿用已授权的分支交付流程。
