## 采集与离线解析结果

采集 10 个唯一官方来源：6 个设备/SaaS 定价页，4 个计费、席位/通知权限和留存文档。项目内模型调用为 0，未下载权重、生成报告或写入生产索引。辅助网页工具用于交叉核查，不能冒充项目静态抓取结果。

初次静态请求 10 个页面均返回 HTTP 200；6 个定价页都没有提取出 `price_rows`。为定位清洗损失，又对定价页进行 DOM 诊断；GitHub 的这一请求和一次重试失败，现有 fetch 返回的错误字符串为空。本版本如实记为 `unknown_fetch_error`。最终选用的资料中，9 个原生采集成功，GitHub 保留失败记录及独立网页工具短节选。

最终可保存诊断的 **5 个成功原生定价页**，逐条报价和结构化金额覆盖均为 **0/5**；另有 **1 个原生抓取失败** 单列，未混入分母。该结果属于特意选取的小型静态采集诊断，不是生产完整浏览器抓取流程或整个 RAG 的得分。

## 补充资料及适用范围

- [Notion 计费帮助](https://www.notion.com/help/billing)：保留周期与自动续订短证据；全文另外涉及席位与增减成员计费。计费机制不能补出具体套餐价格。
- [Figma Dev Mode 指南](https://help.figma.com/hc/en-us/articles/15023124644247-Guide-to-Dev-Mode-in-Figma)：保留 Full/Dev 席位对应 ready for dev 通知的一条短证据。通知条件不等于所有 Dev Mode 功能的资格，不能把 Viewer 视图权限混入通知资格。
- [Slack 留存设置](https://slack.com/intl/en-gb/help/articles/203457187-Customise-data-retention-in-Slack)：保留免费版 90 天或一年留存的短证据；历史可见、物理删除及例外仍须分别取证。
- [GitHub 许可证计费](https://docs.github.com/en/billing/reference/github-license-users)：原 URL 已重定向到新文档；保留组织/企业计划按许可证席位计费的证据。计划费之外的订阅和使用量不能从这一条推算。

所有样本均为 `candidate`，`reviewed_by=null`，没有新增人审 gold。价格的税费、地区与交互状态保持未知；抓取时间没有被填为来源发布时间。002 的渠道、时间窗及到手价，038 的完整客户账单仍缺失。

## RAG 在本项目的作用

RAG 在回答或分析时检索外部资料并将证据交给模型，不改变模型权重。原始研究将模型参数中的知识与可检索资料结合，讨论来源和知识更新问题：[RAG 原论文](https://arxiv.org/abs/2005.11401)。模型的联网工具同样可以提供外部上下文；DeepSeek 官方工具包区分网页搜索与页面抓取：[工具说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/web/tool-web/README.md)。

项目中的实际分工应是：模型理解任务与分析，web search/fetch 获取当前公开资料，检索服务复用内部或历史证据，workflow 的共享快照让各 agent 使用同一版本，QA 回读来源核对结论。检索得分不代表事实已被核验；使用 RAG 也不能自动消除错误推理或陈旧信息。

数据量小会降低复杂向量检索相对直接提供上下文的收益，但数据量不是当前主要瓶颈。已保存的本地对照在 16 条资料、5 道曝光审核题上，E5-small 与 BGE-M3 的 dense Recall@5 均为 1.0；两份记录都明确 `answer_generated=false`、`whole_rag_verified=false`。这是小样本召回成绩，不代表生产已启用该模型、已正确生成报告或已节省 token。

本次真实采集又显示：报价在清洗时丢失后，扩大库或换 embedding 都不能恢复缺失事实。优先需要提高可用证据比例，再验证历史报告和内部资料是否让调研结论更好。

## 下一阶段优先级

1. **按目标事实检查抓取是否有效。** 有 HTTP 200 和正文仍可能没有报价；价格缺口应触发有界的 DOM/表格保留或一次浏览器补采。优先处理本轮能证明的清洗损失，不扩成通用爬虫改造。
2. **保留报价与结构关系。** 在明确的套餐卡片、表格行和设备配置中绑定字段；验证周期/地区选中状态，分离总价、分期、优惠和配送费。不能仅拼接跨行文字后默认条件正确。
3. **同题比较 RAG 净收益。** 后续使用新审核样本比较：LLM 直接回答、LLM 加相同联网工具、LLM 加联网工具与内部 RAG。固定模型及预算，分别测试公开新事实、内部资料、跨期变化/冲突、无答案场景；记录事实正确、引用支持、时效、澄清/拒答、实际 token、请求数和耗时。未测量前不宣称节省百分比。

评测量随问题覆盖增加，不设“库到多少条 RAG 才有用”的硬门槛。少量独有内部资料也可能有价值；单次报告只需少量公开网页时，可保留简单检索路径，依据对照结果决定复杂度。
