# 稀疏检索后续与 Agent 对齐离线计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development。用户已确认继续，按复现、最小修复、冻结资料、独立审查、最终验证的顺序执行。

**Goal:** 处理剩余复杂稀疏查询与缺实体情况，建立未参与本轮调优的新真实候选问题集，验证真实 Agent 入口与证据对齐，保持离线。

**Architecture:** 继续使用共享检索服务、Collector 准入和证据快照。查询中的产品事实、范围及输出指令分别处理；缺少实体时仅进行可解释的主题召回或保守返回缺口，不能从金标反推产品。资料整理与查询实现分工，新增候选集在实现者不可见的目录先冻结；基线代码从当前提交只读导出，避免与正在修改的代码混用。

**Tech Stack:** SQLite FTS5、Qdrant 本机持久化、本机 E5/BGE、pytest、既有 Agent 与 benchmark 入口。

- [ ] 先补 `test_retrieval_intent.py` / `test_knowledge_lexical_recall.py` 的通用失败例：无品牌的明确领域主题、纯问题语气、未知中文实体、多产品歧义、格式中的“保留”、型号/数量约束。
- [ ] 运行 `PYTHONPATH=backend:backend/tests/unit ../plan_a/.venv/bin/python -m pytest backend/tests/unit/test_retrieval_intent.py backend/tests/unit/test_knowledge_lexical_recall.py -q`，保存 RED，再实施最小通用修复。
- [ ] 不为 GitHub、题号或来源 URL 写特例，不修改旧三份独立样本；不把所有词改成 OR，不放松 scope、版本、来源角色或时效保护。
- [ ] 修改策略时更新查询/词法版本及缓存身份，相关旧关键词、数值、目标产品、全文与缓存测试全绿后锁版。

## 2. 新真实候选问题集与防止调优泄漏

- [ ] 仅检查仓库与本机项目中已保存的官方原文及出处，不联网、不下载、不调用外部模型。先区分连续原文、短节选、作者摘要及合成资料。
- [ ] 从未用于旧问答标签的事实片段准备至少 12 道候选；如离线资料不足则记录实际数量，不为凑数伪造资料。保留出处、原文范围、采集时间及核验局限。
- [ ] 将新题、标签和证据先保存到私有临时目录，计算哈希并冻结；资料整理者不改查询实现，实现者不读取新题/答案。
- [ ] 标签保持 `candidate`，不虚构独立人审。已见来源和未见问题分开说明，不能称第三方盲测；后续用于调优的题需退出保留集。
- [ ] 在当前 Git 提交的只读代码副本上跑基线；最终锁版再跑同一数据，用同一参数比较稀疏/混合/精排、宽范围/明确产品范围，区分候选覆盖与最终 top-3。

## 3. 各 Agent 检索与证据对齐

- [ ] 新增独立集成测试，使用实际 RAG 工具与 SQLite、真实准入/快照/产物依赖，模型和抓取仅使用声明过的固定离线重放。
- [ ] 验证 Collector 按产品×维度选资料，Analyst/Comparator/Reflector/Writer/QA 仅消费对应已准入事实；Planner/Survey 按其实际职责记录，不虚称其执行自由 RAG。
- [ ] 覆盖错产品、错项目/工作区、旧报告替代一手资料、过期资料、变更版本/哈希、证据退休或更正、原始来源投毒、未提供事实引用与条件错绑。
- [ ] 尽量执行真实写作 hardening/发布校验；如存在替换，逐项列出，不能把重放通过写成真实 LLM 事实准确率。
- [ ] 生成各阶段使用的 snapshot/source/fact ID、回退/跳过、缺口与拒绝原因摘要，检查失效产物不会被复用。

## 边界

本阶段不提高工作区月度额度、不跑付费四家联网流程、不启动 HTTP Qdrant/Temporal 部署验收、不下载新权重。既有本机官方资料只证明保存时的快照内容，不证明现在仍然有效。新候选未经用户独立审核时只能做诊断，不能覆盖旧人审记录或宣称 RAG 合格。
