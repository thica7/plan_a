# 有界语义提取、维度缺口与定向补证交付结果

日期：2026-10-10。分支：`codex/pastoral-desktop`。沿用既有隔离工作区，保留此前修改；本轮未提交或推送。

## 结论

本轮四项功能已实现并完成回归：有界模型语义提取、按产品/维度查看内容与缺口、定向补证、带缺口报告生成。

**真实任务能生成草稿，但完整产品调研报告仍未通过验收。** 最后一轮 Notion / Confluence / Coda 真实任务生成 1481 字符报告，正文引用可解析，未知来源引用为 0，保留 `completed_with_blockers`。它仍漏用了已采集的 Notion、Confluence 功能资料，当前价格也不完整；不得把任务终态、引用 ID 有效或测试通过视为事实质量合格。

下一步优先修复下游证据分配与能力对齐。继续扩大数据量、增加模型搜索次数或放松缺价门禁，都不能解决当前“已有资料未进入结论”的问题。

## 已实施内容

### 1. 有界模型语义提取

- 确定性提取后，对已登记且产品身份匹配的官方功能文档补提取。只处理一般 `feature`，不让模型自由改写价格。
- 输入上限 12000 字符，每页最多 6 条事实；每产品/维度最多尝试 2 页，30 秒超时，服务端与模型传输均执行 1600 输出 Token 上限。
- 缓存按产品、维度、正文哈希识别；重绑定本次页面身份，失败尝试也消耗额度。复用原有 trace 和总预算，记录 `collector.semantic_extract` prompt 标识。
- 模型选择原文；服务端重新核验 URL、产品归属、原文偏移、完整行边界及邻近上下文。改写、他产品内容、价格与指令文本被拒绝。
- 保留引文前后完整邻近行（最多 1600 字符）与窗口内识别出的条件行，不截断条件以凑预算。条件行超限时拒绝语义补提取，已有确定性证据继续保留。
- 字段身份由页面 URL 与原文哈希构成，防止不同页面的第 1 条事实误成同一属性冲突。**该身份不是跨产品的统一能力分类。**

窗口内的条件识别使用有限关键词，并不证明整篇网页或产品套餐的所有前提均已理解。语义补提取仍需真实样本审核。

### 2. 按维度查看内容与缺口

报告阅读器新增“按维度查看内容与缺口”：产品、维度、已采纳片段、来源与条件并列显示。退役及非当前有效来源不冒充已核验资料；演示任务显示“演示内容（非真实核验）”。新交互文案提供中文和英文，沿用明亮像素主题。

定向补证沿用现有重做入口，只提交当前分支的 issue IDs；运行中、重做次数耗尽时禁用，失败有反馈，完成后可继续处理剩余缺口。浏览器已目视检查中文面板与演示标记；真实联网测试使用临时存储，未导入业务运行列表。

### 3. 定向补证与部分证据报告

- 缺口描述进入定向搜索；价格问题明确要求套餐、货币、计费周期与席位条件。
- 重置所选分支的研究额度和语义缓存，保持其它分支；总调用、Token 和费用预算继续累计。
- 维度级问题在 scoped redo 中绑定所选竞品，防止补 Coda 的价格时清除 Notion 的价格分支。
- 仅在存在真实已采纳事实、剩余阻塞均为允许的收集缺口、重试已耗尽时生成草稿。全无证据、产品身份错误、原始引用失效仍阻断。
- 缺失分支不消耗分析模型、不制造结论；缺证据的比较维度清空赢家。Writer 接收具体缺口；blocker 保留，最终状态为 `completed_with_blockers`。

### 4. 验收中修复的下游问题

- Writer 重复携带完整证据与回答边界时，先缩小证据选择，再检查完整上下文容量；控制条件保留，实在装不下仍拒绝。
- 本地确定性 QA 使用独立的单来源审查容量，不因为生成模型的 8KB 视图过小就退役有效来源。生成模型仍遵守原深度预算。
- 最终覆盖检查使用**当前封存证据快照**，包括正文没有引用的来源；正文引用仍检查 Writer 的**原始快照**、生产凭据、规范来源与 AnswerBoundary。两种审查不互相替代。
- 真实网页捕获的知识库引用无法绑定时，保留原始网页证据并标记引用异常；从知识库检索出的资料不允许绕开规范引用检查。

最后修复没有再重跑整条联网流水线，而是冻结真实输出做离线复核；本项外部模型调用为 0：

- R4 分析检查点重放确认已有 Notion 功能分析不再误判为空，仍保留真实价格缺口。
- R5 用最新 QA 重新审查：原报告正文完全不变，问题数 **50 → 16**；原先 Notion/Confluence 的假“未采集功能证据”消失，只剩真实价格缺口及其它比较/质量问题。删除误报不代表剩余内容已合格。
- 参数化回归覆盖补采后当前快照与旧 Writer 快照不同的情况，防止覆盖检查又退回旧版本。

## 当前问题与下一步优先级

1. **先解决已采资料漏用。** 全局 8KB 视图按产品/字段排序填充，Coda 可占先；下游凭据要求完整事实依赖，部分视图又可能丢弃 Notion/Confluence 的整个分析。改为按产品/维度分配证据容量、显式记录本轮省略、复用已验证的分支摘要；必要时按维度分段写作。验收要求三产品已有功能事实均进入正文，“视图省略”不得写成“没有资料”。
2. **再做可比能力对齐。** 哈希和 `capability_1` 不能直接代表同一个产品能力。建立当前任务需要的少量统一能力项（如共同编辑、评论、权限、知识组织），将原始事实保留来源与条件地映射进去；不存在对应证据时保持未知。验收必须包含相关但不可比、同名不同条件的反例。
3. **补当前价格的完整条件。** 继续官方价格页/渲染抓取，核验套餐、席位、人数、地区、货币、周期与税费；不把免费介绍、功能文档或搜索摘要当完整报价。
4. **修复预算调度与质量误报。** 为 Analyst、Comparator、Writer 预留预算，停止已耗尽分支的无效搜索回退；用真实样本校准关键词自洽检查，区分结构错误、证据错误和低风险文案问题，保留来源与引用保护。

下一轮采用冻结 R5 资料先做离线证据覆盖回归，再执行受限的模型写作复验，最后才复跑完整联网任务。当前不需要新增密钥、额外服务或用户整理更多资料。
