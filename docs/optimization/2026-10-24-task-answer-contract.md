## 1. 实际改动

### Writer：明确交付已审核局部结论

- `task_projection.py` 复用当前运行、快照、消费、任务身份、主张摘要及真实独立审核输入／输出校验，返回有完整凭据的任务结果。没有放宽来源准入或引用支持。
- `task_answers.py` 把任务结论、对象、原问片段和完整已支持主张显示在完整原题下。正文和最终 QA 使用同一展示／匹配函数，隔离草稿使用 live 凭据。整题未核实仍可看到已审核子任务结果，但局部支持不自动升级为整题已回答。
- 最终语义审核的连续完整原问分段由服务端构造，模型只回传有序、完整的 `segment_id`，服务端恢复原文后执行原 v3 守卫。不能通过自行回传整题 `question_quote` 合并相反分支；坏同行、非字符串问题 ID 单独失效，字符串 foreign／重复 ID 保留原拒绝策略。
- 真实回放中 Bitwarden 的明确容量否定已进入正文，Trello 的 A/B、导出及部分权限结论也实际可见。最终整题状态仍可能为未核实，尚未完成统一的整题语义判断。

### Reflector／Writer／QA：共同诊断与修复依据

- `question_state.py` 共享“上下文未送达、证据待核实、来源上下文可用、已审核局部答案、整题状态”的有限表示。来源可用不能授予结论资格，反思阶段尚未写作也不能据此判采集失败。
- 局部修复接收独立审核的具体规则错误、失败检查和理由，带 `repair_only_not_evidence`；不从审核理由生成事实。仍最多一轮、两个失败／部分任务，成功同行与已有合格支持保留。
- 这些改变统一了表示和可见结果的依据，**没有证明三个 Agent 的语义结论已经一致**。本轮仍有越出所选引用的主张、整题未核实和反思回退。

### 最终 QA：同题共享、最多两批

- 每题仅携带本题已回答主张与经过完整凭据重放的同题任务支持；同题 finding 可共享完整上下文。原问、引用原句、角色／套餐／范围条件不裁断。
- 每批 6000 bytes、最多两批。实际派送、模型返回合法审核、未送审及失败分别留存；另一批返回的 finding ID 不取得本批资格。缓存复用不计新 transport，未知 usage 保守计费。
- `diagnostic_only` 仍不能解除阻断。收据中的 `model_execution=completed` 表示存在合法模型结果，**不表示所有项完成**；还必须看 `model_reviewed_issue_ids`、`model_unreviewed_issue_ids` 和 `unsent_issue_ids`。
- 首轮 Trello 把其他题的全部可见支持复制到每题候选，导致窗口装不下、最终 QA 0 次。该回归先通过离线用例复现，再以同题归属补修；最终 Trello 实际调用两次，仍有三项未送。

### 预算：保留明确最终载荷额度

- 新运行最终回答预留 12000 token；完整回答审核请求最多 10000 UTF-8 bytes，加 256 记账余量和 1600 输出，上限 11856。超窗明确不发起审核，不截来源条件。
- 最终 QA 保持 10000 预留；全局仍为每家 24 次调用／80000 token，原重试和输出限制不增加。旧 checkpoint 的 20000 回答及已有 QA 预留保持，恢复不把它们转为前阶段可花额度。
- 实际 admission／transport 回放验证了尾部任务进入、最终额度保护、在途崩溃与旧额度恢复。但最终 Trello 仍有两次零 transport 预算拒绝，延期没有根治。

## 4. 下一步

优先解决任务原子性与逐题覆盖：复合主张应拆成可独立审核的任务结果；缺失的子问必须显式恢复，不能以“已有一个 no”替代整题。其次，最终模型审核应对实际问题独立安排，不能依赖 Reflector 恰好产出历史 finding；需要明确处理反思回退、部分批次失败与未送项。最后按真实剩余任务及完整载荷安排预算，避免扩大批次后继续饿死尾部。

继续保留精确来源、前提及拒答边界。当前证据不支持默认开启实验、提高置信度自评或开始 Agentic RL。
