# 官方来源到 Writer：真实模型验收记录

## 结论

**新产品官方来源入口与真实 Writer 链路已接通；报告仍未达到交付标准。**

本轮新增配置驱动的精确文档登记、实际抓取回执、缓存与完整正文入库前复核。最终运行确实经过 Collector、完整正文持久化、共享快照、Analyst、Comparator、Reflector、受保护的 Writer 入口、逐条主张审核和最终 QA。模型审核仍漏掉已知条件，Airtable 缺证也未解除；没有发布报告或把项目用户的参考答案确认冒充正文人审。

具体实现和新增产品方法见 [官方来源登记](2026-10-16-official-source-registry.md)；全部尝试的统计及文件哈希见 [结构化结果](2026-10-16-official-writer-results.json)。

## 本轮变更

- 产品身份从“只有代码内置产品”扩展为“代码内置产品 + 部署者审核的精确文档登记”。登记覆盖 Miro、Airtable、Trello、Zoom；只对实际登记链接授权，不信任任意同域 URL、请求 hint 或模型自称。
- 缺失真实网页标题不再用候选标题补写。新产品 capture 必须通过 URL、标题、成功响应、完整材料、质量及正文哈希检查；模型摘要/unknown 材料不能成为完整网页证据。
- 同一核验函数进入真实 capture、缓存重绑定、语义提取前检查与完整正文入库前检查。原 canonical 的 scope、角色、版本、URL/哈希校验继续执行；没有以手填支持状态或升高置信度触发 Writer。
- 新增默认零调用的真实采集测试入口，强制人审数据、输入/登记哈希、临时存储、原生调用预算、总超时和失败后 QA。它显式关闭向量索引，避免继承外部 embedding/Qdrant 配置；生产语义 RAG 本轮未验收。
- 修复测试中发现的句首 `Zoom in/out` 误识别、内置产品别名碰撞、capture-only 总超时、零来源仍付费跑下游、无 Writer 依赖时统计误报，以及测试 Writer 入口未提交生产者依赖的问题。

## 实际采集

固定输入是已人审 8 题中的 001、002、004、005，只把问题和来源标识交给运行时；没有发送参考答案、预期结果、禁止推断或人工短节选。

两次 capture-only（模型调用均为 0）先后记录网络状态：首次 Miro 403；第二次成功取得两份 Miro 完整官方正文。两份 Airtable 资料始终被现有 robots 检查拒绝。本轮没有绕开 robots、使用失败页或把浏览器/web 工具展示内容冒充生产 Collector 采集。

Miro 后续再次 403 时，浏览器回退被沙箱阻止启动；在允许所需浏览器运行权限后，最终真实流程成功取得两份 Miro 正文。HTTP 与浏览器路径均保留原安全和内容检查。这说明网络可用性会变化，不代表每次访问或所有新产品都能可靠采集。

## 最终运行的链路证据

- 2 份 Miro `webpage_verified`、typed `full_source`，真实完整正文进入隔离 canonical SQLite；快照有 **30 条事实**，不是 30 个独立答案。
- Collector 2 次、Miro Analyst 1 次、Comparator 1 次、Reflector 1 次、Writer 1 次、逐条审核 1 次；实际模型调用全部成功。Airtable Analyst 因无准入证据明确跳过，没有伪装为模型执行。
- Writer 使用 `_real_writer_step`，实际证据投影、消费凭据与 Writer dependency 存在，最终 QA 能重放核对；引用 ID 属于对应产品，未发现未知引用。
- 4 条主张被模型判 `supported`，正文 2356 字；这仍是未发布的诊断草稿，不是已验收报告。
- QA 共 7 项问题，其中两个 blocker：Airtable 没有 feature 来源；Airtable 比较单元缺失。无来源的产品保留缺口，没有凭空补完比较。

## 前提归属与引用语义检查

**模型审查通过不等于这次报告正确。** 根据用户已经认可的参考边界检查，仍有以下问题：

1. **001 的套餐前提丢失**：正文把公开链接下编辑/评论的泛述直接发布，未保留 paid/Education 条件，不能回答 Free 看板的实际权限问题。相关限制确实在原始全文，且有一条绑定的条件与审核输入已含限制，模型依然判通过；不能归咎于“缺少资料”。跨章节 FAQ 的泛述也没有正确合并前文权限规则。
2. **002 的关键答案没有输出**：Guest 需登录、只能访问直接获邀看板，原始全文与写作/审核输入均有这些信息，正文却没有完整回答 A/B 访问范围。这里是输出覆盖遗漏，没有证据表明它直接断言 Guest 可以免登录。
3. **角色与条件结构仍有疑点**：Guest 邀请主张的一条 `operation_binding.role=members` 来自“非团队成员”的语境；原文中的接收者描述被当成了操作角色。矩阵又同时显示套餐/角色未核实，仍发布了正向操作文本。显式 ID 绑定还不足以保证前提语义一致。
4. **004/005 缺证，不能评分通过**：Airtable 网页不可采集，未形成可用于本轮实际模型回答的证据。其余 003/006/007/008 未进入本次生成范围。不能以 4 条模型支持主张计算 8 题准确率。

上述是 Codex 及独立代码审查代理对运行产物的核对，不冒充第三方人审。用户此前认可的是参考答案边界，尚未审核这份生成正文；未给正式语义准确率或交付通过标签。

## 测试、审查与保密

相关测试包含新增功能的 RED→GREEN、官方登记/非法 URL/别名/query 文章隔离、材料/标题/哈希伪造、缓存跨产品、引用输入答案隔离、原生预算、总超时、零来源成本保护与 Writer 受保护提交。最终代码后端 **4293 通过、1 跳过、202 条既有警告**，跳过实机 Postgres RLS 连接测试；相关入口/登记/历史诊断 **67 项通过**，它们也包含在全量测试内，不相加计算。实际配置凭据扫描 1182 个文本文件，未发现当前密钥或被追踪的秘密配置；Git diff 空白检查通过。

原始抓取正文、canonical SQLite、trace、草稿和逐条审核保存于 Git 忽略的 `data/artifacts/official-writer-2026-10-16/`，不会上传完整网页和诊断正文。公开结果只记录统计、问题与文件哈希。既有脱敏器会遮盖部分 Airtable 数字文章 ID；导出 JSON 不是原始字节，原始 URL/正文以 canonical 库核对。

独立审查确认新增登记与测试入口当前没有开放 P1/P2；两项正文语义 P2 保留为未修复结果问题。实际调用/正文/快照/canonical、原生 Writer 依赖和正文篡改后的拒绝均单独核对。不能把新增入口的代码审查通过解释为生成报告已通过。

## 下一步优先级

1. **先修结构化前提与主张审核**：把操作主体、接收者和排除对象分开；将同操作/角色的跨章节限制绑定为可验证前提，逐条审核必须对照完整前提清单，未知或不完整的能力不发布正向结论。
2. **再修问题覆盖与局部报告**：按待回答问题分配写作容量，确保 Guest 登录/看板访问这样的已采关键答案进入正文；缺证报告应更短，不能用重复“待核验”和整段用户简报填充。
3. **补合规可用的来源入口**：为 robots/403 阻断保存原因并允许有来源身份记录的人工上传或合规 API/导出；不得把另一来源的网页展示冒充被阻断页的真实采集。
4. 在这些修复后，用新增且独立人审的题、反例和真实模型重新验收。当前工程贯通不替代自动发现、生产语义 RAG、完整 Graph 及部署验收。
