## 下一批工作合同

### 1. 数据与标注

问题草案位置：`eval/product-research-queries-draft.jsonl`。字段为 `id`、`category`、`product`、`dimension`、`market`、`as_of`、`query`、`review_status`、`label_status`、`purpose`。

草案中的产品名称和问题不是事实结论；`iphone duo` 等消歧题没有预先断言产品存在或不存在。标注前必须核实产品、市场、日期和来源。

正式评测需要另外保存固定资料集合与审核标签：

- 资料：稳定 source ID、URL、全文或可核对节选、来源角色、完整型号、市场、原发布 / 更新 / 抓取日期与内容 hash。
- 标签：原始查询、相关 source / chunk、支持答案的原文位置、预期事实或澄清 / 无足够证据的结果、审核者及审核日期。
- 待审核与已审核资料不能混算；空相关列表不能同时表示“尚未标注”和“已确认无答案”。
- 用于验收的标签与未来训练、参数调整数据分开。50 条是首轮样本起点，不是模型训练充分性的保证。

我负责官方资料采集、候选标注和检查；需要人工核对代表样本及事实口径。没有完成审核的样本保留其实际状态，不以 AI 自评代替人工审核身份。

### 2. 清洗与分块

优先保留原结构和完整含义：标题、套餐、表头、单元格单位、价格条件、脚注、型号和市场。清洗只去除明确无关导航和重复内容，不能把不同版本或价格冲突当成重复记录删除。

先补中文无空格分句、英文小数和型号、价格限制条件、表格跨块的失败用例；每个改动以检索命中后的原文能回查为验收条件。超长表格不能通过无标记截断绕过预算。

首轮保留字符上限作为兼容接口；模型未就绪时不声称采用真实 tokenizer。接入真实模型后按实际 tokenizer 评测长度。已有 chunk、原快照及真实索引不会自动重切，新的分块策略用隔离资料集验证。

### 3. 检索与模型

复用现有知识仓库、FTS、Qdrant、RRF 和 reranker 接口，不另建第二套事实服务。正式评测应使用共同资料池与干扰样本，不能只给每个查询一个很小的专属资料库。

比较关键词、真实 dense、RRF 混合和混合 + 真实精排；保留原始查询，不用标准答案扩展查询。范围过滤在召回前执行；型号、市场、时效和引用版本沿用原契约。

真实模型验收必须记录 requested / effective provider、模型版本、维度和索引版本。实际回退为 hash 时报告为降级或不可验收，不能继续输出“真实语义通过”。模型和分块改变后建立隔离索引，不混用旧模型向量。

### 4. 评测

检索先看 Recall@k、MRR、nDCG 和无足够证据 / 消歧行为；按产品类型、语言、市场、型号及日期分组，再记录 p50 / p95 延迟、索引耗时和资源。

报告层再检查关键事实、引用原文、时效和比较口径，并在独立离线样本上使用 Ragas。Faithfulness 只说明上下文支持，不能证明来源仍然正确。现有确定性检查继续作为快速门禁，不给每次报告新增整套付费裁判。
