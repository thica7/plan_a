# 子问前提绑定与正文／QA 一致性

日期：2026-10-23。基线 `03fa684`，分支 `codex/pastoral-desktop`。

**结论：工程改动和测试已完成，本轮报告仍未达到交付标准。** 最终原始八题严格通过3题；不能把引用完整率当作回答完整率。

## 实施范围

1. **可读证据选择**：短引用发送实际 quote 与 support_ref，服务器恢复原始坐标、事实和来源。四家完整 Writer 输入与历史基线比对，原候选零损失；没有增加上下文或生成预算。
2. **逐子问前提**：保存原问连续片段、该片段选择的已发表主张、结论、关系和来源摘要。验证完整覆盖、引用并集、父子结论与重放身份；明确限制跨子问借否定、跨范围容量、建议或否定形式的伪上限及 can→must。服务端规则是有限拒绝器，完整语义仍需审核。
3. **隔离未发表资料**：答案复审只用精确绑定支持；完整父段落和未发表草稿不能补答案。可验证的时间/例外约束只用于拒绝或限定。操作支持也不能把原始父段落带回来。
4. **正文与 QA 一致**：共享问题块渲染和检查；已选推断从最终答案发表，未入答案的推断不另作结论。事实观察仍可显示。修改状态、裸结论、引用或复制到其它产品都不能通过同一重放。
5. **保留格式要求**：带“是否”等字样的展示指令附回原问题，不能额外制造问题；真正新问题仍保留。

新增字段兼容历史记录。完整 audit 仍进入 Writer 产物摘要，因此删除新合同标记或篡改父决策会使原依赖失效；子问摘要本身只绑定该子问的输入与证据，不证明语义正确。

## 尚未解决与下一优先级

1. **拆清并列对象并逐项发表**：Trello将A/B两个投票结果合成一个depends，仍会被标为answered。连续文本分段和摘要不能保证每个决策对象独立覆盖，需进一步建立请求谓词/对象清单与逐项结果，再检查交付状态。
2. **缺口驱动的局部选证与重写**：1Password的单库/私人库仍引用到邀请规则；Trello第二题已有页面资料但未发表。应对失败子问按明确缺失前提重新选证、重写受影响原子并审核，避免只扩充全局提示或整份重跑。
3. **统一最终QA的时点**：正文、保存记录及答案重放已共用结果，但总QA仍保留早期Reflector对容量、域权限、投票义务的过时或错误判断。须让最终QA重新核对这些问题级结论，保留独立来源/矩阵问题，不能直接清空早期blocker。
4. **服务端事实也进入同一引用合同**：Cloudflare缺账单正确，却附带未精确绑定的CPU计费事实；1Password拒答需保留公开页面的报价性质与可执行下一步。不能仅靠服务器生成就豁免支持审核。

本轮没有自动修补这些语义缺口或将其标为已完成；不进行训练。下一阶段应优先按上述失败轨迹验证通用修复，再增加未曝光样本。
