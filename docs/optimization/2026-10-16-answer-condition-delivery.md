## 范围与结论口径

本轮按已批准计划修复已采资料到正文的遗漏、操作前提归属、逐条主张与引用审核，以及局部报告表达。工程测试、真实模型诊断、参考边界人审和生成正文验收分别记录。

用户已确认 Basecamp / GitBook 六题参考边界；输入文件只更新审核状态、审核人和记录时间，题目、来源及参考答案不变。该确认不代表生成报告通过人审。样本准备者看过参考资料，不能称为盲测或第三方独立验收。测试入口仅向 Agent 传问题、产品及来源标识，参考答案和短节选不进入生产输入。

## 生产改动

1. **Collector 条件结构**：同页规则提取与模型提取使用独立身份，合并时不再丢模型补充；两个身份均保留位置、引文和值的准入重放。邀请资料可通过功能相关性词法检查，但仍需事实准入。区分操作主体、接收者和排除对象；具名角色的 need/require 不能作为其他角色前提；明确的审批、授权后再操作关系按目标角色与操作绑定。完整独立原句保留来源坐标并单独准入，旧混合快照需要重新采集/提取。
2. **Writer 答案选择**：功能问题按产品作用域、独立子问和代词继承建立待答清单。联合问题在各产品保留；三种研究深度均使用受保护的分维度入口。先从已准入快照选择问题相关的完整观察，再分配有界写作包；选择提示不充当事实。每问最多三条、合计最多八条，未命中或超容量保持未核实。
3. **逐条审核**：操作、角色、对象、正反效果及必要前提有稳定检查 ID。检查须恰好出现一次，并指向主张中的真实文字片段；缺项、未知检查、错归及可识别矛盾拒绝。精确片段和模型 supported 仍不是通用语义证明。
4. **回答覆盖**：独立有界审核只读取已支持主张及所有绑定原文/条件，不重复未采用的候选操作。每个问题记录 answered / partial / unanswered / unverified，引用只能指向已发表主张。最终 QA 检查问题范围和覆盖；写作遗漏路由 writer_only，不能冒充 Collector 缺证。
5. **局部报告**：省去长主题复制、重复空矩阵和机会模板，展示已审核事实与未完成问题。覆盖不完整继续保留阻断；没有任何可发表事实时，现有 preflight 仍拒绝发布正文。
6. **运行冻结**：实际问题保留产品前缀，按加入前缀后的 500 字上限校验；不截断任务。输入、官方登记、生产代码和实际依赖的诊断/预算脚本共同冻结，漂移拒绝运行。问题超输入容量时跳过模型并完整记录 unverified，不增加额度。

## 测试方法

真实诊断使用官方完整网页，经现有 production Collector adapter、提取准入和 canonical 存储进入快照，再执行采集 QA、Analyst、Comparator、Reflector、受保护 Writer、逐条审核和最终 QA。来源由人审登记的精确 URL 固定，未执行 Planner 自动发现、搜索发现、Survey、完整 Graph 调度或生产语义 RAG 检索；不能称为完整主流水线验收。

### 最后真实结果与剩余问题

- **Miro v3**：抽取去重修复后 75 条事实进入快照，Writer 已输出登录、直接获邀与套餐相关候选。但模型返回 9 条，原解析器最多 8 条且整包拒收，最后没有经过逐条审核的正式正文。不能按先前 v2 的 Guest 成功覆盖冒充最后整份报告成功。
- **Basecamp v2**：邀请页现在通过准入，来源由 2 增至 3，事实由 15 增至 51，旧账号例外已经进入正文。但模型把文件夹规则误标为已回答“私有消息 X”，项目 B 的已采规则未进入写作视图，且一般 Admin 限制和旧账号例外的表达尚未正确合并。两个 `answered` 标签不能充当语义验收。
- **GitBook v2**：授权后端、登录和拒绝未授权访客已进入正文，并保留了 Authenticated access 的适用范围。定价页抓取成功但没有合格提取事实；Essential 的 Chat 资格未核实，人民币含税月费题也没有形成明确的“资料不足”回答。仍有与具体问题无关的观察。

## 下一步优先级

1. **验证回答是否真正解决问题**：覆盖审核要核对用户问题中的对象、条件和要求的结论；不能用“同一产品且相关”通过。为 private message / folder、日期例外和“资料不足”准备匿名独立反例。
2. **问题导向证据分配与有限修复**：当前每问三条的词法选择仍会遗漏已采事实，应比较现有多语 embedding / 精排在“问题→准入事实”层的效果；覆盖缺口只触发对应问题的有限补写或补证，并保留预算。
3. **扩展结构绑定的表达力**：目前六类操作对 Admin 资格、内容私有状态和日期例外的覆盖不足；需绑定原子事实及其原始条件，不能让模型凭已有 ID 跳过审核。补齐定价页原文提取后再测 Chat 资格；缺报价时直接给简短的不足结论，不推测金额。
4. **再验收完整主图**：上述报告问题稳定后，再用真正的 Planner→搜索发现→完整 Graph、生产语义 RAG 和用户正文审核验证。当前诊断不能代替完整主图、多人部署、Qdrant HTTP、Redis、Temporal 或 Docker 验收。
