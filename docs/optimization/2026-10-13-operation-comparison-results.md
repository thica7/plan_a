# 同口径能力比较与缺口驱动补证：交付记录

开始：2026-10-12；记录：2026-10-13（Asia/Shanghai）。

## 结论

通用功能已实施，离线回归通过；**真实报告交付验收未通过**。新产品 Nuclino 复用了相同代码和官方入口配置，但不能据此声称新产品完整流程稳定或采购报告合格。

最终四家真实 v6 在 analyst 阶段达到 token 准入上限：已存储 10 个来源（Notion 4、Confluence 3、Coda 2、Nuclino 1），未生成报告。三家 v4 生成带阻断项草稿，Confluence 报价缺证，剩余额度不足以审核三家的功能内容。

## 实施内容

- 阅读、评论、编辑文档、创建、分享文档、权限管理分别投影，原文、角色、套餐、访问对象及前提保留。缺失不等于不支持，不同角色或审批条件不能自动等同。
- 否定按动作分句处理；角色转折、复合访问角色、句内前提保留。“编辑时无需分享”不建立分享能力；编辑评论、分享评论链接不填入文档编辑/分享格。
- 语义证据先准入，再判定补证。`documented` 语义字段纳入原有能力质量检查，仍需独立原文准入。
- 明确操作缺口转现有 QualityGap → RepairTask。预留一次搜索、一个候选位置；剩余抓取、候选、搜索与修复轮数仍有界。无候选容量不做搜索，失败保留缺口，成功重新准入和计算验收条件。
- 补证新源在原网络额度内最多额外保留一个，避免被原来源目标数量截断。既有来源保留，未请求操作的任务保持原规则。
- 新可信官方帮助文档只有在服务端操作补证范围下才能进行语义准入，重放不信任模型提供的授权元数据。
- Nuclino 只登记官方入口，没有预设功能答案。精确已登记网址可以绑定没有品牌名的帮助页标题；未登记、伪域、其他产品仍拒绝。
- 比较矩阵存储 operation_alignment；正文操作格必须绑定已审核、同产品/维度/操作的主张与来源。极简、适中、深入及单维度操作任务统一进入逐条审核写作。
- 修复旧结构化 writer 绕路以及审核后硬化追加派生段落。操作报告保留已审正文、缺口与合法出处，不用旧深挖、矩阵或 SWOT 补全冒充审核结果。一般完整报告的原章节规则保持。

本轮“通用”范围为跨厂商的文档协作操作对照；没有把六种文档操作强称为所有产品类别的完整能力模型。

## 人工报告质量检查

1. 三家中间 v1–v3 的 completed 不代表最终通过；权限操作仍有对象或条件缺口，若干产品审核缺失。
2. 四家 v4 虽 completed，仅 Nuclino 有 8 条模型审核通过主张；其余三家没有已审核观察。旧硬化还追加了未审核段落，不能作为交付结果。该路径已修复。
3. Nuclino 部分主张只是添加/编辑/回复评论的步骤，没有补全同任务的文档权限能力。最终对象过滤防止把编辑评论当编辑文档，但操作/角色/套餐结构化抽取仍需加强。
4. 四家 v5 因 DeepSeek DNS 失败中断；随后本机 DNS、匿名 HTTPS 连接恢复，进行了有界复验。
5. 四家最终 v6 在分析阶段预算耗尽，无报告。三家 v4 存在 Confluence pricing blocker，不能给完整采购结论。
6. 缺口驱动补证的真实调用已经发生，但尚未稳定补齐角色、套餐与访问条件；没有宣称真实缺口关闭率达标。

## 下一阶段优先顺序

1. **为写作和逐条审核预留 token**，给原生搜索/collector/analyst 分阶段上限；真实调用无 usage 或失败后的保守扣费应可解释。额度不足提前收缩任务或保存有效草稿，避免到分析/写作时整体失去交付机会。
2. **增强操作对象与前提的结构化抽取**：优先角色、套餐、页面/文档/评论对象、访问/审批规则，避免 UI 步骤挤占比较证据；用原文跨度验证模型提议，保留无法判定项。扩大真实固定评测集，检验缺口关闭率和误填率。
3. **补证局部更新与去重**：保存补前/补后验收、来源及失败理由，只更新受影响分支；减少社区/泛搜索对权限和报价任务的预算竞争。
4. **独立的报告交付状态**：有草稿、内部可读、正式交付分别判断，缺少必要产品审核、操作条件或报价条件时不能因 completed 自动放行。
5. 之后核验十人团队收费角色、适用套餐、账期、地区和税费，稳定生成完整账单。该部分没有在本轮伪造完成。
