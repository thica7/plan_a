# 子问证据分配、原子主张与 QA 归属交付

日期：2026-10-23。基线 `62d97d6`；分支 `codex/pastoral-desktop`。

**本轮工程改造及四家真实阶段回放已完成；报告仍未达到完整交付标准。** CPU计费规则已经进入正式报告，Trello的A/B投票与下载、导出恢复，但义务判断及第二题仍遗漏；Cloudflare权限答案在最终审核预算不足时没有发表。工程回归通过不能替代内容验收。

## 实际改动

1. **按子问保留完整资料。** 新增 `question_allocation.py`，从原问生成有限动作、命名对象及独立谓词任务，先安排各任务的完整原文，再填普通背景。Task、请求和检索命中均不构成产品事实；引用提示仅来自当次实际派送目录。无问题ID的既有内部调用保持兼容，不制造假问题身份。
2. **元数据与资料共用实际窗口。** 定向修复保留失败原问、失败草稿、失败检查及原支持；完整长评语保留在审计历史。元数据、完整fact及合法支持在同一实际压缩窗口装入，不再分别估算后回填；可选排序提示只用剩余容量。不截原文、AND/OR前提或例外。初写、修复与派送回执统一14KB最终门，32KiB本地视图不扩大模型写作窗口。
3. **单谓词生成与审核。** 初写最多8个原子、修复最多4个；下载和导出分别成原子，不把前提列表拆成多个无条件句。修复超额整批拒绝，单列 `question_repair_atom_capacity_exceeded`。文档摘录的沉默不能支持“整页没有义务”；有限拒绝守卫区分来源文档与产品导出文档，避免误拒有原文支持的内容排除规则。模型仍会生成复合主张，这项合同并不保证全部遵从。
4. **CPU完整行进入实际Writer。** 复用计费适用性、同模式、表头、CPU列及完整脚注守卫，将合格CPU行先加入当前问题core候选，再保留完整可引用行。免费CPU、异套餐、异模式、缺表头和单独脚注不能代替该行。新正式CPU主张通过审核后才可由不足账单答复复制；仍不计算完整账单。
5. **题设与来源事实分开。** 首两家真实诊断暴露初写审核缺少原问。现在服务端解析后的计划把具体claim ID绑定到原问，只有匹配的 `kind=inference` 获得条件场景；事实、假设、未绑定或外来问题不获授权。题设不进入facts、quotes或support_quotes，原子须写明自己的条件；上下文只解代词，不补未知角色。初写与修复审核均接同一入口。
6. **分开两种缺项。** Cloudflare首次修复把CPU、税费等账单资料缺项填进严格请求澄清字段，整份计划被拒。新增 `question_plan_missing_fields` 仅从既有请求澄清规则计算，保留原答案资料缺项但禁止抄作计划字段；解析器没有放宽。
7. **QA按问题归属重放。** 新增 `qa/question_context.py`，验证当前快照、选择／消费凭据、成功实际派送及完整原文、操作和引用。只有精确服务器必要澄清可关闭自身core遗漏的覆盖误阻；事实缺口、例外、未知归属、旧回执及篡改继续阻断。原gap与遥测保留，不能凭answered标签消除。

入口与合同见 [Agent执行说明](../agent-execution.md)。实现计划见 [计划及实际补充](2026-10-23-subquestion-allocation-plan.md)。

### 仍然存在的问题

- **生成任务没有变成可靠的执行约束。** 模型仍可能补无关背景、超过原子配额或把多个谓词塞进一条。Trello的义务及计费分支需要可执行的逐任务交付和明确deferred状态，不能继续只加提示词。
- **精确引用合法不代表整句成立。** Trello“而非成员类型”不在该主张选择的原段中；表格Requests计量名与Workers Paid范围也必须分清选中引用、结构表头合同及限制上下文，不能用父段补新的谓词。逐条内容结果见结构化记录。
- **审核预算可能使已支持结论消失。** Cloudflare权限推理已通过主张审核，但后续答案审核未实际调用，最终保守未发表；Trello另有两次QA入场拒绝。预算保护仍不足以保证最终逐题答复完成。
- **QA误阻只修复了明确归属的一类。** Bitwarden没有再出现旧core gap的回答覆盖blocker，但仍有比较矩阵blocker和旧反思warn。不能宣称全部QA语义一致性已解决，也不能将真实缺问／矩阵问题一律忽略。
- **来源缺口仍需正向补证。** 1Password当前封存资料没有合格公开报价来源；保持金额未知。安全拒价不是整道报价研究题的完成。
