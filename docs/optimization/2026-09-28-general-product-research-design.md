# 通用产品竞品研究设计

日期：2026-09-28。已获用户确认，实施分支 `codex/product-research-generalization`。

## 目标

用户输入一个目标产品，系统先识别其品类、用户、使用场景和地域，再发现与它有可解释替代关系的竞品。产品可以是软件、服务、消费应用或实物。AI 只作为研究工具，不作为被研究产品的默认品类。

## 研究契约

`RunCreateRequest.target_product` 为可选结构：`name` 必填，`official_url`、`category`、`audience`、`use_cases`、`market` 可选。旧 API 请求仍可运行。新建运行界面要求名称，并将研究重点 `topic` 与产品画像分开。`AnalysisPlan` 保存目标产品，Temporal 输入完整传递该字段，活跃运行指纹纳入产品身份。

官方 URL 是用户提供的候选提示，不因为输入者填写就标记为已验证。内置公司/产品名单仅提供种子资料；名单外产品继续进入检索和核验。无可验证搜索结果的候选保留为待核验，不能挂靠其他候选的资料。

## 发现流程

1. 使用产品名称、品类和使用场景构造相互独立的发现查询，去重搜索结果。
2. 候选同时标注关系：`direct`、`adjacent`、`substitute`、`unverified`。关系说明必须包括共同用户/任务和主要差异。
3. 搜索结果必须确实与候选名称、别名或官网域名匹配；否则该候选没有搜索证据。仅有模型建议的名称保留给人工审核，不进入自动采集。
4. 若没有足够候选，明确返回发现不足；用户可提供竞品，不能借用不相关网页充数。
5. 不按内置名单过滤竞品。官网验证状态独立记录，后续采集可利用用户提供的未验证提示，但正式引用仍需要抓取和证据准入。

## 通用品类抽取

产品画像决定研究查询与特征抽取。无品类的旧运行保持当前行为以兼容历史报告；指定通用品类的运行使用从网页正文提取的通用能力事实和可核对原文，不产生“上下文窗口、模型调用”等不适用字段。价格、功能、用户场景继续作为跨品类公共维度；尚无证据的字段显示为未知。

## Agent 证据和时效

- 来源质量包含内容可用性、来源权限、抓取方式、原文位置、发布时间、页面更新时间、抓取时间、事实核验时间。
- KB 命中分数用于排序，不能直接转为接近 1 的事实置信度。复用 KB 的事实应保留原始来源与观察日期。
- 易变事实优先使用已重新核验的页面；仅重新抓取历史文章不能证明其中旧价格仍有效。
- 抓取先走轻量 HTTP；登录页、验证码、软 404 和导航空壳视为不可用。必要时调用浏览器抓取；其子进程有总超时和清理。
- 抓取结果明确区分成功、内容不足、权限限制、浏览器依赖缺失和超时。
- 搜索可根据品类和事实类型传递日期、语言、地区及官网域名过滤；过滤不可用时记录降级状态。

## 错误与质量门禁

候选无证据、页面受限、当前信息缺失时，报告输出“待核验/未找到公开证据”及下一步取证动作。不得把无证据推断写成产品事实。价格和功能下线等变化保留旧值、新值及适用日期，冲突未解决时阻止发布。

## 验收

- 至少四类固定离线样本：普通 SaaS、消费应用、电商工具、实物产品。
- `Cursor + Notion` 候选不会因名单原因丢失 `Notion`；不相干文章不会成为其证据。
- 非 AI 产品不会被强制映射到 AI 专有功能字段。
- 登录页文字较长时仍视为抓取失败或不足，浏览器降级有总超时。
- 旧请求、Temporal 往返、来源引用与局部重做回归通过。
- 评测记录候选相关性、误归属率、事实支持率、陈旧事实误用和抓取结果分类。

像素视觉后续以《星露谷物语》式场景与材质为方向，保留工作台数据的易读性。这部分在两条核心流程验收后实施。
