## 实现与实际入口

### Collector：恢复精确原文并保留历史收据

新增布局映射只恢复唯一、完整、同窗口的连续原文。保持词界、数字及标点种类；拒绝改词、否定变化、数字并合、跨空行／标题／代码、重复片段与截窗。最终引用仍为 `quote.text == body[start:end]`，原始模型提案保留在诊断中。

默认提取版本为 `question-focus-v2:<focus>`；历史v1保持原精确／Markdown策略。准入与逐题收据重放按typed `extractor_version`运行对应策略，未知版本拒绝，普通metadata不能选择策略。独立审查发现并修复了旧提案在新版规则下改变ID的问题。

上轮封存Collector六条提案，旧策略实际准入1/6，新策略6/6；全部有精确原文坐标并通过真实准入。测试贯通 `semantic → admission → RawSource → SQLite → seal_snapshot`。这是同批提案的定位恢复，不代表新模型必能提取所有问题答案，也不授予完整抓取／入库功能通过。

### 子问：完整候选包与共同任务说明

许可／义务任务按局部请求选择主动作，完整父题设继续保留为假设上下文。服务端 `task_instruction`同时进入selector、Writer和任务QA；计费任务按适用规则／前提选证，不要求先算出完整账单。角色／套餐假设无需官方证明，产品规则仍须完整所选来源。

每任务先构造完整候选包，再按规范事实与原始片段合并、去重并重新分配引用别名。共享事实保留各子问需要的完整片段与例外闭包；容量冲突有限拆批，单包超界明确延期。候选JSON及其前缀上限10000 bytes；任务生成／审核user窗口14000 bytes，SYSTEM另计。完整候选仅指当前可见范围，不能保证上游快照相关事实全部入窗；本轮仍在更早的逐题检索发现漏证。

新版任务说明使用固定SYSTEM身份，投影及QA重放重新绑定规范任务身份、说明、原题、上游产物与实际派送。修复轮允许有限拆批，总计最多两个唯一任务、每任务一次；历史协议保持原行为。篡改说明、同步篡改focus及说明、重复修复与超额修复均有反例测试。

### Writer／QA：完整分窗、无损共享与同一预算算法

尾答按完整问题装窗，保留父题设、全部必要分支、该题已审主张及支持／限制。来源审核通过但任务未完成的partial局部事实也保留，不提升为完整答案。同窗不能借另一题的claim。超界仅延期该题，其余完整窗口继续。

每个尾答完整system／user消息上限10000 bytes；尾答保护12000保持。最后一窗后才结束该阶段；中途取消保留保守消费，恢复可复用精确相同输入的有效结果。预算预检与实际reserve共用消息、有效输出上限、live record、repair／phase计算，预检不增加消费。连空生成消息都无法准入时，在付费选证之前明确延期；这只是可证明的下界，不保证完整所选包随后一定可发送。

最终QA将完整父题设纳入共享context，按独立问题优先回填现有窗口，保留6000 bytes／最多六批。不同context不合并，候选及ID可逐字段恢复。新版语义协议v3阻止直接复用旧版审核缓存；明确请求假设不需来源证明，有界逻辑推论仍需产品规则支持。完整QA请求保护为11608，旧checkpoint费用和显式保护原样保留。

未知usage、超时或取消仍保守计费；原总额度无法保证最坏情况下所有窗口都送达，必须保留未审及恢复状态。

## 失败源头及下一阶段建议

1. **已入库事实在子Agent视图之前丢失。** Trello逐人逐板／Workspace禁止规则两条规范fact仍在snapshot，最早可见掉点为 `question_fact_retrieval` span37：degraded lexical、12 eligible／12候选、每题限3，选出集合已无这两条；随后Writer projection、view及实际selector catalog都缺。未记录逐候选分数，具体ranking理由未验。不能归因Collector未入库，也不能说LLM见过该原句仍拒答。
2. **生成任务粒度和审核合同冲突。** Trello Writer虽只收到vote任务仍复述全部能力；1Password将容量与私有库合并，Bitwarden修复加core feature独立谓词，导致有限复合守卫拒绝。部分合理结论伴随额外未选断言：Cloudflare No稿加入未选given-scope规则，Requests稿加入未选inbound／subrequest；Bitwarden选collections段却借另一未选段证明one other user。不能把这些整句当成有证好稿而指责所有门禁误杀。
3. **多阶段重复和无进展修复耗尽交付资源。** 生成与尾答仍有10条零派送；保护最终QA全送没有解决可发表答案不足。继续加Prompt、门禁或提高总额度不能作为本轮合格证据。
4. **必要澄清与机制状态未统一。** BW2正文符合边界，但diagnostic候选和待澄清状态仍被独立QA视为不完成；Comparator／live Reflector还会把视图缺失或合法推论误判缺证。

建议下一阶段先收敛为：**完整原题与子问共享可审计证据池 → 一次生成多个明确原子主张及各自支持／推论 → 独立逐条审核 → 确定性投影正文**。记录规范fact从检索、候选、selected到发表每步的去向；将事实不足、必要澄清、合理推论及未审核分别表达。减少逐个小谓词重复走全部角色与修复的成本，按完整链路安排预算。随后再做同版同资料的轻量路线／完整流水线对照和未曝光独立样本。本轮仅提出该下一阶段，不继续改提示或重跑已曝光题凑成绩，暂不训练模型。
